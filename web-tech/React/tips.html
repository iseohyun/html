1React · 목록 · 폼 · 팁 · map과 key
목록과 key
  • 목록: 배열의 map으로 데이터 하나를 JSX 하나로 바꿔 그림
  • key: 항목마다 변하지 않는 고유한 값을 붙여, React가 다시 그릴 때 같은 항목을 알아보게 함
src/TodoList.jsx
const todos = [ { id: 7, text: '우유' }, { id: 8, text: '빵' },] function TodoList() { return ( <ul> {todos.map(todo => ( <li key={todo.id}>{todo.text}</li> ))} </ul> )}

첫 번째 슬라이드는 목록입니다. 화면에 같은 모양이 반복될 때는 데이터를 배열에 담고, Javascript 기초문법의 배열 함수 map으로 항목 하나를 JSX 하나로 바꿉니다. JSX가 값이기 때문에 배열에 담을 수 있고, React는 JSX의 배열을 차례로 그려 줍니다.

이때 각 항목에 key를 붙여야 합니다. 붙이지 않으면 콘솔에 경고가 나옵니다. key는 React가 다시 그릴 때 "이 항목이 아까의 어느 항목인가"를 알아보는 이름표입니다.

오른쪽 위는 key로 배열의 순번을 썼을 때입니다. 맨 앞에 달걀을 추가하면 순번이 하나씩 밀립니다. React는 0번이 여전히 0번이라고 보고, 내용만 우유에서 달걀로 바뀌었다고 판단합니다. 줄마다 입력창이나 체크 상태가 있었다면 엉뚱한 항목에 남습니다.

오른쪽 아래처럼 데이터가 가진 고유한 id를 key로 쓰면, React는 9번만 새로 만들고 7번과 8번은 그대로 옮깁니다. 그래서 key에는 데이터베이스의 id처럼 항목이 생길 때 정해져 변하지 않는 값을 씁니다.

2026-11-18 · key 는 형제 사이에서만 고유하면 됩니다

첨부 · key의 규칙
  • 형제 사이에서 고유해야 합니다. 서로 다른 목록끼리는 겹쳐도 됩니다.
  • 변하지 않아야 합니다. 그릴 때마다 Math.random()이나 Date.now()로 만들면 매번 새 항목으로 보여 전부 다시 만듭니다.
  • 순번(index)은 목록의 순서가 바뀌지 않고 추가 · 삭제도 없을 때만 써도 됩니다.
  • key는 React가 쓰는 값이라 props로 전달되지 않습니다. 자식에서 그 값이 필요하면 id={todo.id}처럼 따로 넘깁니다.
  • 새 항목을 만들 때 id가 없다면 crypto.randomUUID()로 만드는 시점에 한 번 정해 데이터에 넣습니다.
첨부 · 걸러서 · 정렬해서 그리기 
function TodoList({ todos, showDone }) {
  const visible = todos
    .filter(todo => showDone || !todo.done)
    .toSorted((a, b) => a.text.localeCompare(b.text));

  if (visible.length === 0) return <p>할 일이 없습니다</p>;

  return (
    <ul>
      {visible.map(todo => (
        <li key={todo.id}>{todo.text}</li>
      ))}
    </ul>
  );
}

visible은 props에서 계산한 값이므로 state로 두지 않습니다. sort는 원본 배열을 고치므로 toSorted를 쓰거나 [...todos].sort()처럼 복사한 뒤 정렬합니다.

폼: 입력 값을 state와 묶기

2React · 목록 · 폼 · 팁 · 제어 컴포넌트
폼: 입력 값을 state와 묶기
  • 제어 컴포넌트: 입력창의 value에 state를 넣고, onChange에서 state를 바꿈
  • 원본은 하나: 입력창이 값을 따로 갖지 않으므로, 같은 값을 화면 어디서든 바로 쓸 수 있음
src/NameForm.jsx
function NameForm() { const [name, setName] = useState('') return ( <form> <input value={name} onChange={e => setName(e.target.value)} /> <p>안녕하세요, {name}님</p> </form> )}

두 번째 슬라이드는 폼입니다. Javascript 객체 접근의 폼 예시에서는 제출할 때 입력창을 찾아 value를 읽었습니다. React에서는 입력 값을 처음부터 state에 둡니다.

방법은 두 줄입니다. 입력창의 value에 state를 넣고, onChange에서 방금 입력된 값으로 state를 바꿉니다. 이렇게 React의 state가 값을 쥐고 있는 입력창을 제어 컴포넌트라고 합니다.

오른쪽 그림을 한 바퀴 돌아 봅니다. 글자를 치면 onChange가 새 값을 전달하고, setName이 state를 바꾸고, 다시 그려진 입력창이 그 state를 보여 줍니다. 입력창은 state를 비추는 거울입니다. 그래서 value만 적고 onChange를 빠뜨리면 글자가 써지지 않습니다.

번거로워 보이지만 값의 원본이 state 하나뿐이라는 이점이 큽니다. 아래 인사말처럼 같은 값을 다른 곳에 바로 쓸 수 있고, setName에 넘기기 전에 대문자로 바꾸거나 길이를 제한할 수 있고, 값이 비었을 때 단추를 비활성화하는 것도 식 하나로 끝납니다.

첨부 · 예시 — 입력이 여러 개인 폼 
function SignupForm() {
  const [form, setForm] = useState({ name: '', email: '', agree: false });

  function handleChange(e) {
    const { name, type, value, checked } = e.target;
    setForm({ ...form, [name]: type === 'checkbox' ? checked : value });
  }

  function handleSubmit(e) {
    e.preventDefault();
    console.log(form);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="name" value={form.name} onChange={handleChange} />
      <input name="email" value={form.email} onChange={handleChange} />
      <label>
        <input type="checkbox" name="agree" checked={form.agree} onChange={handleChange} />
        동의합니다
      </label>
      <button disabled={!form.agree}>가입</button>
    </form>
  );
}

입력창의 name 속성을 state 객체의 키와 맞추면 핸들러 하나로 모두 처리할 수 있습니다. [name]은 변수의 값을 키로 쓰는 문법입니다.

첨부 · 제출할 때만 읽어도 되는 경우

입력 도중에 값을 쓸 일이 없다면 state 없이 제출할 때 한꺼번에 읽을 수 있습니다. 브라우저의 FormData를 씁니다.

function handleSubmit(e) {
  e.preventDefault();
  const data = new FormData(e.target);
  console.log(data.get('name'), data.get('email'));
}

<form onSubmit={handleSubmit}>
  <input name="name" defaultValue="" />
  <input name="email" />
  <button>보내기</button>
</form>

처음 값은 value가 아니라 defaultValue(체크박스는 defaultChecked)로 줍니다. React 19에서는 <form action={함수}>처럼 함수를 직접 넘기면 그 함수가 FormData를 인자로 받습니다.

세 번째 슬라이드는 다음에 배울 것들의 지도입니다. 지금까지 다룬 컴포넌트, props, state, effect가 가운데의 핵심입니다. 이 네 가지만으로도 한 화면짜리 앱은 충분히 만들 수 있습니다.

위쪽은 앱이 커지면 만나는 문제입니다. 주소에 따라 화면을 바꾸려면 라우팅 라이브러리가, 서버 데이터를 캐시하고 로딩 상태를 다루려면 데이터 라이브러리가 필요합니다. 여러 단계를 건너 props를 내려 주기 번거로워지면 Context나 전역 상태 라이브러리를 씁니다.

아래쪽은 개발 방식에 관한 선택입니다. CSS를 컴포넌트 단위로 나누는 방법, TypeScript로 props의 모양을 미리 검사하는 방법, 그리고 이 모두를 묶어서 제공하는 프레임워크가 있습니다.

한꺼번에 배울 필요는 없습니다. 핵심만으로 작은 앱을 하나 끝까지 만들고, 불편이 생긴 지점에서 그 불편을 푸는 도구를 하나씩 더합니다. 도구가 왜 필요한지를 먼저 겪어야 그 도구의 사용법이 이해됩니다.

첨부 · 참조 — Context: props를 여러 단계 건너뛰기

테마나 로그인한 사용자처럼 트리 곳곳에서 쓰는 값은, 중간 컴포넌트를 모두 거쳐 props로 내려 주기가 번거롭습니다. Context는 위에서 값을 제공하고 아래 어디서든 꺼내 쓰게 해 줍니다.

import { createContext, useContext, useState } from 'react';

const ThemeContext = createContext('light');          // ① 만들기

export default function App() {
  const [theme, setTheme] = useState('light');
  return (
    <ThemeContext value={theme}>                      {/* ② 제공하기 */}
      <Page />
      <button onClick={() => setTheme('dark')}>어둡게</button>
    </ThemeContext>
  );
}

function Title() {                                    // 몇 단계 아래에 있어도
  const theme = useContext(ThemeContext);             // ③ 꺼내 쓰기
  return <h1 className={theme}>제목</h1>;
}

React 18까지는 <ThemeContext.Provider value={theme}>로 적었습니다. 편리하지만 데이터가 어디서 오는지 코드에 드러나지 않게 되므로, 먼저 props로 해 보고 불편할 때 씁니다.

첨부 · 참조 — 커스텀 Hook: 반복되는 로직 뽑기

여러 컴포넌트에 같은 state와 effect 조합이 반복되면 use로 시작하는 함수로 뽑습니다. 「effect와 생명주기」의 창 크기 구독을 Hook으로 만들면 다음과 같습니다.

function useWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);

  useEffect(() => {
    const onResize = () => setWidth(window.innerWidth);
    window.addEventListener('resize', onResize);
    return () => window.removeEventListener('resize', onResize);
  }, []);

  return width;
}

function Layout() {
  const width = useWindowWidth();
  return width < 600 ? <MobileMenu /> : <DesktopMenu />;
}

커스텀 Hook은 state 자체가 아니라 state를 다루는 로직을 공유합니다. 두 컴포넌트가 같은 Hook을 불러도 state는 따로 가집니다.
