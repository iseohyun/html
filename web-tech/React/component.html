JSX는 HTML처럼 보이는 Javascript

1React · JSX와 컴포넌트 · JSX
JSX는 HTML처럼 보이는 Javascript
  • 정체: JSX는 빌드할 때 함수 호출로 바뀌고, 실행하면 화면을 설명하는 객체(React 요소)가 됨
  • 중괄호: { } 안에는 Javascript 식을 적고, 속성 이름은 className처럼 Javascript 규칙을 따름
src/App.jsx
const name = '서현' function App() { return ( <section className="card"> <h1>안녕, {name}</h1> <p>{2 + 3}개의 새 글</p> <img src="/logo.svg" alt="로고" /> </section> )}

첫 번째 슬라이드는 JSX입니다. 왼쪽 코드에서 return 뒤의 내용은 HTML처럼 보이지만 Javascript 파일 안에 있습니다. 이렇게 Javascript 안에 태그를 적는 문법을 JSX라고 합니다.

브라우저는 JSX를 읽지 못합니다. 그래서 빌드 도구가 오른쪽 그림의 두 번째 상자처럼 함수 호출로 바꿉니다. 태그 이름은 첫 번째 인자가 되고, 속성과 자식은 두 번째 인자의 객체가 됩니다.

이 함수를 실행한 결과는 DOM 요소가 아니라, 화면이 어떤 모습이어야 하는지를 적은 가벼운 객체입니다. React는 이 객체를 앞의 것과 비교해 달라진 곳만 실제 DOM에 반영합니다. JSX가 결국 Javascript 값이기 때문에 변수에 담거나 함수가 돌려줄 수 있습니다.

규칙은 두 가지를 먼저 기억합니다. 첫째, 중괄호 안에는 변수나 계산식 같은 Javascript 식을 적습니다. 둘째, 속성은 객체의 키가 되므로 Javascript 규칙을 따릅니다. class는 예약어이므로 className으로 쓰고, img처럼 내용이 없는 태그도 반드시 />로 닫습니다.

style의 중괄호가 두 겹인 것은 특별한 문법이 아닙니다. 바깥 중괄호는 "Javascript 식을 넣는다", 안쪽 중괄호는 "그 식이 객체다"입니다. CSS 속성 이름도 background-color가 아니라 backgroundColor로 씁니다.

첨부 · 조건에 따라 그리기

JSX 안에는 if 문을 쓸 수 없습니다. 중괄호 안에는 값이 되는 식만 들어가기 때문입니다. Javascript 기초문법의 연산자를 그대로 씁니다.

삼항 연산자: 둘 중 하나
{isLogin ? <p>환영합니다</p> : <p>로그인해 주세요</p>}
&& 연산자: 있거나 없거나
{count > 0 && <span className="badge">{count}</span>}
미리 변수에 담기
let message;
if (isLogin) message = <p>환영합니다</p>;
else message = <p>로그인해 주세요</p>;

return <div>{message}</div>;

&&의 왼쪽이 숫자 0이면 화면에 0이 그려집니다. count && … 대신 count > 0 && …처럼 참·거짓이 되게 적습니다. null, undefined, true, false는 아무것도 그리지 않습니다.

컴포넌트와 props

2React · JSX와 컴포넌트 · props
컴포넌트와 props
  • 컴포넌트: JSX를 돌려주는 함수. 이름을 대문자로 시작하면 태그처럼 쓸 수 있음
  • props: 태그의 속성으로 적은 값이 객체 하나로 묶여 함수의 인자로 전달됨 (읽기 전용)
src/App.jsx
function Card({ title, children }) { return ( <article className="card"> <h2>{title}</h2> {children} </article> )}export default function App() { return ( <Card title="공지"> <p>내일은 쉽니다</p> </Card> )}

두 번째 슬라이드는 컴포넌트와 props입니다. 컴포넌트는 JSX를 돌려주는 함수입니다. Javascript 기초문법에서 배운 함수와 같고, 이름을 대문자로 시작한다는 점만 다릅니다. 소문자로 시작하면 React가 div 같은 HTML 태그로 여깁니다.

만든 컴포넌트는 태그처럼 씁니다. 아래쪽 App에서 Card를 태그로 적고, HTML 태그에 속성을 주듯이 title을 적었습니다.

태그에 적은 속성은 객체 하나로 묶여 함수의 첫 번째 인자로 들어옵니다. 이 객체를 props라고 부릅니다. 함수 선언의 중괄호는 그 객체에서 필요한 값을 꺼내는 구조 분해 문법입니다.

여는 태그와 닫는 태그 사이에 적은 내용은 children이라는 이름으로 전달됩니다. Card는 그 내용이 무엇인지 몰라도 정해진 자리에 그려 주기만 하면 됩니다. 테두리나 배치처럼 겉모습만 맡는 컴포넌트를 만들 때 씁니다.

마지막으로, props는 읽기 전용입니다. 자식이 title에 새 값을 대입해서는 안 됩니다. 값을 바꿔야 한다면 부모가 새 값을 넘겨야 하고, 그 방법은 다음 문서의 state에서 다룹니다.

2026-11-18 · 한 파일에 컴포넌트를 여러 개 적어도 되지만, 커지면 파일을 나눕니다

첨부 · 문법 (Syntax)
컴포넌트를 정의할 때
function 이름({ 속성1, 속성2 = 기본값 }) {
  return ( JSX );
}
컴포넌트를 쓸 때
<이름 속성1="문자열" 속성2={식} />
<이름 속성1="문자열">자식 내용</이름>
  • 이름은 대문자로 시작합니다 (Card, UserList).
  • 문자열은 따옴표로, 그 밖의 값(숫자, 변수, 객체, 함수)은 중괄호로 넘깁니다: count={3}, user={user}, onSave={handleSave}
  • 값 없이 이름만 적으면 true입니다: <Button disabled />
  • 객체를 펼쳐 한꺼번에 넘길 수 있습니다: <Card {...cardProps} />
  • 컴포넌트 안에서 다른 컴포넌트를 정의하지 않습니다. 다시 그릴 때마다 새 함수가 되어 state가 초기화됩니다. 파일의 최상위에 정의합니다.
첨부 · 파일 나누기 — export와 import

컴포넌트가 늘어나면 파일 하나에 컴포넌트 하나를 둡니다. HTML에서 <script src>로 파일을 불러왔다면, 여기서는 ES 모듈의 export와 import를 씁니다.

src/Card.jsx
export default function Card({ title, children }) {
  return <article className="card"><h2>{title}</h2>{children}</article>;
}
src/App.jsx
import Card from './Card.jsx';
import './App.css';          // CSS도 import 한다
방식내보내기가져오기특징
defaultexport default function Cardimport Card from './Card.jsx'파일에 하나. 가져올 때 이름을 바꿀 수 있음
namedexport function Cardimport { Card } from './Card.jsx'여러 개 가능. 이름이 같아야 함
첨부 · 컴포넌트는 순수해야 합니다

React는 컴포넌트를 언제, 몇 번 부를지 스스로 정합니다. 그래서 컴포넌트는 같은 props에 같은 결과를 돌려주고, 부르는 것만으로 바깥을 바꾸지 않아야 합니다.

나쁜 예: 그릴 때마다 바깥 변수를 바꾼다
let guest = 0;
function Cup() {
  guest = guest + 1;            // 호출 횟수에 따라 결과가 달라진다
  return <h2>{guest}번 손님의 컵</h2>;
}
좋은 예: 필요한 값은 props로 받는다
function Cup({ guest }) {
  return <h2>{guest}번 손님의 컵</h2>;
}

StrictMode가 컴포넌트를 두 번 부르는 이유가 이 규칙을 지키는지 확인하기 위해서입니다.

컴포넌트 트리와 데이터의 방향

3React · JSX와 컴포넌트 · 단방향 흐름
컴포넌트 트리와 데이터의 방향
  • 아래로: 데이터는 props를 타고 부모에서 자식으로만 흐름
  • 위로: 자식이 부모에게 알릴 일이 있으면, 부모가 props로 내려 준 함수를 호출

세 번째 슬라이드는 컴포넌트가 모였을 때의 모습입니다. HTML의 태그가 부모와 자식으로 겹쳐 트리를 이루듯, 컴포넌트도 트리를 이룹니다. 맨 위의 App이 Header와 TodoList를 품고, TodoList가 다시 TodoItem을 품습니다.

이 트리에서 데이터는 한 방향으로만 흐릅니다. 파란 화살표처럼 부모가 props로 자식에게 내려 주고, 자식은 받은 값을 읽기만 합니다. 형제끼리 직접 주고받는 길은 없습니다. 그래서 어떤 값이 이상할 때는 위쪽으로 거슬러 올라가며 찾으면 됩니다.

자식에서 일어난 일을 부모가 알아야 할 때는, 부모가 함수를 props로 내려 주고 자식이 그 함수를 호출합니다. 그림에서 TodoItem의 삭제 단추를 누르면 주황색 점선처럼 onDelete가 호출되고, 실제로 목록을 고치는 일은 데이터를 가진 App이 합니다.

Javascript 이벤트 문서의 이벤트 전달과 비교하면, DOM에서는 이벤트가 부모로 저절로 올라갔지만 React의 컴포넌트 사이에서는 함수를 명시적으로 내려 주어야 합니다. 번거로워 보이지만 누가 데이터를 고치는지가 코드에 그대로 드러납니다.

2026-11-18 · 데이터를 어디에 둘지는 다음 문서 「state와 이벤트」에서 정합니다

첨부 · 예시 코드 — 그림의 트리 
function TodoItem({ item, onDelete }) {
  return (
    <li>
      {item.text}
      <button onClick={() => onDelete(item.id)}>삭제</button>
    </li>
  );
}

function TodoList({ items, onDelete }) {
  return (
    <ul>
      {items.map(item => (
        <TodoItem key={item.id} item={item} onDelete={onDelete} />
      ))}
    </ul>
  );
}

function Header({ count }) {
  return <h1>할 일 {count}개</h1>;
}

export default function App() {
  const items = [{ id: 1, text: '우유 사기' }, { id: 2, text: '산책' }];
  const handleDelete = id => console.log(id + '번을 지워 달라는 요청');

  return (
    <>
      <Header count={items.length} />
      <TodoList items={items} onDelete={handleDelete} />
    </>
  );
}

아직 state가 없어 실제로 지워지지는 않습니다. 콘솔에 요청이 찍히는 것까지 확인하고 다음 문서로 넘어갑니다.

첨부 · 화면을 컴포넌트로 나누는 기준
  1. 한 가지 일: 컴포넌트 하나는 한 가지 일만 합니다. 설명에 "그리고"가 들어가면 나눌 때입니다.
  2. 반복: 같은 모양이 두 번 이상 나오면 컴포넌트로 뽑습니다 (목록의 항목, 카드, 단추).
  3. 데이터의 모양: 데이터가 배열이면 "목록"과 "항목" 컴포넌트가, 객체이면 그 객체를 보여 주는 컴포넌트가 자연스럽게 생깁니다.
  4. 이름: 하는 일로 짓습니다. 접두사 on은 props로 받는 함수(onDelete), handle은 그 함수를 구현한 쪽(handleDelete)에 붙이는 것이 관례입니다.
