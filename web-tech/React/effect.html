1React · effect와 생명주기 · 생명주기
컴포넌트의 생애: 마운트 · 업데이트 · 언마운트
  • 두 단계: 렌더(함수를 불러 계산)와 커밋(계산 결과를 DOM에 반영)으로 나뉨
  • effect: 화면에 반영된 뒤에 실행되는 코드. 타이머 · 구독 · 서버 연결처럼 바깥을 건드리는 일을 둠

첫 번째 슬라이드는 컴포넌트의 생애입니다. 컴포넌트는 화면에 처음 나타나고, props나 state가 바뀔 때마다 다시 그려지고, 언젠가 화면에서 사라집니다. 이 세 시기를 마운트, 업데이트, 언마운트라고 부릅니다.

각 시기는 두 단계로 나뉩니다. 렌더는 React가 컴포넌트 함수를 불러 화면의 모습을 계산하는 단계입니다. 커밋은 그 계산 결과를 실제 DOM에 반영하는 단계입니다. 마운트에서는 요소를 새로 추가하고, 업데이트에서는 달라진 곳만 고칩니다.

렌더 단계의 함수는 계산만 해야 합니다. 「JSX와 컴포넌트」에서 본 것처럼 React는 함수를 여러 번 부를 수 있으므로, 그 안에서 타이머를 켜거나 서버에 요청을 보내면 몇 번 실행될지 알 수 없습니다.

그래서 바깥 세계를 건드리는 코드는 effect에 둡니다. effect는 커밋이 끝나 화면에 반영된 뒤에 실행됩니다. 마운트 뒤에 타이머를 켰다면 언마운트 때 꺼야 하므로, effect에는 시작하는 코드와 뒷정리하는 코드를 짝으로 적습니다.

첨부 · 컴포넌트가 다시 그려지는 세 가지 경우
  1. 자신의 state가 바뀌었을 때
  2. 부모가 다시 그려졌을 때 (props가 같아도 기본적으로 다시 그립니다)
  3. 구독하는 Context의 값이 바뀌었을 때

"다시 그린다"는 함수를 다시 부른다는 뜻이지 DOM을 전부 새로 만든다는 뜻이 아닙니다. 결과가 앞과 같으면 DOM은 건드리지 않습니다. 그래서 대부분의 경우 다시 그리는 횟수를 줄이려 애쓸 필요가 없습니다.

useEffect: 바깥 세계와 맞추기

useEffect: 바깥 세계와 맞추기
  • 모양: useEffect(할 일, [의존하는 값]) — 할 일이 돌려주는 함수가 뒷정리
  • 의존성 배열: 배열 안의 값이 바뀐 렌더링 뒤에만 다시 실행. 빈 배열이면 마운트할 때 한 번
src/Clock.jsx
function Clock() { const [now, setNow] = useState(new Date()) useEffect(() => { const id = setInterval(() => { setNow(new Date()) }, 1000) return () => clearInterval(id) }, []) return <p>{now.toLocaleTimeString()}</p>}

두 번째 슬라이드는 useEffect의 사용법입니다. 왼쪽은 현재 시각을 1초마다 갱신하는 시계입니다. 시각은 state에 담고, 1초마다 그 state를 바꿔 줄 타이머가 필요합니다. Javascript 이벤트 문서의 setInterval을 그대로 씁니다.

useEffect의 첫 번째 인자는 할 일을 담은 함수입니다. 컴포넌트가 화면에 반영된 뒤에 실행됩니다. 여기서는 타이머를 켜고, 타이머는 1초마다 setNow를 불러 화면을 다시 그리게 합니다.

할 일 함수가 돌려주는 함수는 뒷정리입니다. 컴포넌트가 화면에서 사라질 때 React가 불러 줍니다. 타이머를 켰으면 끄고, 이벤트를 등록했으면 해제하고, 연결을 열었으면 닫습니다. 시작과 뒷정리는 항상 짝입니다. 뒷정리를 빠뜨리면 사라진 컴포넌트의 타이머가 계속 돌아갑니다.

두 번째 인자는 의존성 배열입니다. effect를 언제 다시 실행할지 정합니다. 시계의 타이머는 한 번만 켜면 되므로 빈 배열을 넘겼고, 마운트할 때 한 번만 실행됩니다.

배열에 값을 적으면 그 값이 바뀐 렌더링 뒤에 다시 실행됩니다. 이때 React는 이전 effect의 뒷정리를 먼저 부른 다음 새 effect를 실행합니다. 배열을 아예 생략하면 렌더링할 때마다 실행되는데, 필요한 경우는 드뭅니다.

2026-11-18 · effect 안에서 읽는 props · state 는 모두 의존성 배열에 적습니다

첨부 · 문법 (Syntax) 
useEffect(() => {
  // 할 일 (setup)
  return () => {
    // 뒷정리 (cleanup) — 없으면 생략
  };
}, [의존하는_값1, 의존하는_값2]);
  • effect 안에서 쓰는 props, state, 그리고 그것들로 계산한 값은 모두 배열에 적습니다. 빠뜨리면 옛 값을 계속 보게 됩니다. ESLint의 react-hooks/exhaustive-deps 규칙이 빠진 값을 알려 줍니다.
  • 할 일 함수에 async를 직접 붙일 수 없습니다. async 함수는 Promise를 돌려주는데, React는 뒷정리 함수를 기대하기 때문입니다. 안에서 따로 선언해 부릅니다.
  • 개발 모드의 StrictMode는 마운트 직후 뒷정리 → 다시 실행을 한 번 더 합니다. 뒷정리가 제대로 짝을 이루는지 확인하기 위해서입니다.
첨부 · 예시 — 서버에서 데이터 가져오기 
function Profile({ userId }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    let ignore = false;                       // 늦게 도착한 응답을 버리기 위한 표시

    async function load() {
      const res = await fetch('/api/users/' + userId);
      const data = await res.json();
      if (!ignore) setUser(data);
    }
    load();

    return () => { ignore = true; };          // userId 가 바뀌면 앞의 요청은 무시
  }, [userId]);

  if (user === null) return <p>불러오는 중…</p>;
  return <h1>{user.name}</h1>;
}

userId가 1에서 2로 바뀌면 요청이 두 번 나가고, 1번의 응답이 더 늦게 올 수 있습니다. 뒷정리에서 ignore를 켜 두면 늦게 온 옛 응답이 화면을 덮어쓰지 않습니다.

실제 서비스에서는 캐시, 재시도, 로딩 상태를 직접 다루기가 번거로워 TanStack Query 같은 라이브러리나 프레임워크의 데이터 기능을 씁니다.

첨부 · 예시 — 창 크기 구독 
function WindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);

  useEffect(() => {
    const onResize = () => setWidth(window.innerWidth);
    window.addEventListener('resize', onResize);
    return () => window.removeEventListener('resize', onResize);
  }, []);

  return <p>창 너비: {width}px</p>;
}

JSX 태그에 붙일 수 없는 대상(window, document)의 이벤트는 이렇게 effect 안에서 addEventListener로 등록하고, 뒷정리에서 해제합니다.

effect가 필요 없는 경우

effect가 필요 없는 경우
  • 질문: "이 코드는 왜 실행되어야 하는가"에 따라 놓을 자리가 정해짐
  • 원칙: 계산은 렌더링 중에, 사용자의 행동은 이벤트 핸들러에서, 바깥과 맞추는 일만 effect에서

세 번째 슬라이드는 effect를 쓰지 말아야 할 때입니다. effect를 배우고 나면 무엇이든 effect에 넣고 싶어지지만, 대부분은 필요하지 않습니다. 코드를 어디에 둘지는 "이 코드는 왜 실행되어야 하는가"를 물어 정합니다.

첫째, 화면에 보일 값을 구하려는 것이라면 렌더링 중에 그냥 계산합니다. 목록의 개수나 걸러 낸 목록은 이미 가진 state에서 바로 구할 수 있습니다. 이것을 별도의 state에 담고 effect로 맞추면, 한 번 그린 뒤 다시 그리게 되어 느려지고 두 값이 어긋날 틈이 생깁니다.

둘째, 사용자가 무언가를 했기 때문이라면 이벤트 핸들러에 둡니다. 저장 단추를 눌러 서버에 요청을 보내는 일은 "눌렀기 때문"이지 "화면에 나타났기 때문"이 아닙니다.

effect는 셋째 경우에만 씁니다. 컴포넌트가 화면에 있는 동안 React 바깥의 무언가와 계속 맞춰야 할 때입니다. 타이머, 창 크기 구독, 채팅 서버 연결, 지도 같은 외부 위젯이 여기에 해당합니다.

2026-11-18 · React 공식 문서의 「You Might Not Need an Effect」 를 요약했습니다

첨부 · 예시 — effect를 걷어 내기
✕ 계산한 값을 state 와 effect 로 맞춘다
const [items, setItems] = useState([]);
const [total, setTotal] = useState(0);

useEffect(() => {
  setTotal(items.length);          // 한 번 그린 뒤 다시 그리게 된다
}, [items]);
○ 렌더링 중에 계산한다
const [items, setItems] = useState([]);
const total = items.length;        // state 가 아니라 그냥 변수

계산이 무거울 때만 useMemo로 결과를 기억해 둡니다. 의존하는 값이 같으면 앞의 결과를 다시 씁니다.

const visible = useMemo(() => items.filter(isVisible), [items]);
첨부 · useRef — 다시 그리지 않고 기억하는 값, 그리고 DOM 손잡이

useRef는 { current: 값 } 모양의 상자를 돌려줍니다. state처럼 렌더링 사이에 값이 보존되지만, 바꿔도 다시 그리지 않습니다. 화면에 보이지 않는 값(타이머 번호, 직전 값)을 담아 둘 때 씁니다.

두 번째 쓰임새는 DOM 요소에 직접 접근하는 것입니다. Javascript 객체 접근의 getElementById를 대신합니다. 초점 이동, 스크롤, 크기 측정처럼 React가 대신해 주지 않는 일에만 씁니다.

import { useRef } from 'react';

function SearchBox() {
  const inputRef = useRef(null);

  return (
    <>
      <input ref={inputRef} />
      <button onClick={() => inputRef.current.focus()}>입력창으로</button>
    </>
  );
}
첨부 · 문제 해결 — effect가 끝없이 실행될 때 
useEffect(() => {
  setCount(count + 1);       // state 를 바꾼다 → 다시 그린다 → effect 가 또 실행된다
});
  • 의존성 배열이 빠져 있지 않은지 확인합니다.
  • 배열에 렌더링마다 새로 만들어지는 객체 · 배열 · 함수가 들어 있으면 매번 "바뀌었다"고 판단합니다. 그 값을 effect 안으로 옮기거나, 객체 대신 그 안의 원시 값(user.id)을 적습니다.
  • effect 안에서 바꾸는 state를 의존성으로도 읽고 있다면, setCount(n => n + 1)처럼 함수로 갱신해 의존성에서 뺍니다.
