useState: 컴포넌트가 기억하는 값

1React · state와 이벤트 · useState
useState: 컴포넌트가 기억하는 값
  • useState: 현재 값과 그 값을 바꾸는 함수를 한 쌍으로 돌려줌 — [count, setCount]
  • 다시 그리기: 바꾸는 함수를 부르면 React가 컴포넌트 함수를 다시 호출해 새 화면을 계산
src/Counter.jsx
import { useState } from 'react' export default function Counter() { const [count, setCount] = useState(0) function handleClick() { setCount(count + 1) } return ( <button onClick={handleClick}> {count}번 눌렀습니다 </button> )}

첫 번째 슬라이드는 state입니다. 앞 문서의 컴포넌트는 받은 props를 그리기만 했습니다. 단추를 누른 횟수처럼 시간이 지나며 바뀌는 값을 컴포넌트가 기억하려면 useState를 씁니다. 괄호 안의 0은 처음 값입니다.

useState는 배열을 돌려줍니다. 첫 번째는 현재 값이고 두 번째는 그 값을 바꾸는 함수입니다. 이름은 자유지만 count와 setCount처럼 짝을 맞추는 것이 관례입니다.

이제 오른쪽 그림을 따라갑니다. 사용자가 단추를 누르면 onClick에 넘겨 둔 handleClick 함수가 실행됩니다.

handleClick은 setCount를 불러 다음 값을 알려 줍니다. 여기서 count = count + 1처럼 변수에 직접 대입하지 않는다는 점이 중요합니다. 직접 대입하면 값은 바뀌어도 React가 그 사실을 알지 못해 화면이 그대로입니다.

setCount를 부르면 React가 Counter 함수를 처음부터 다시 호출합니다. 이번에는 useState가 1을 돌려주고, 함수는 1이 들어간 새 JSX를 돌려줍니다. React가 앞의 결과와 비교해 글자 부분만 DOM에 반영합니다.

첨부 · 문법 (Syntax) 
const [값, set값] = useState(처음값);
  • 처음값은 첫 렌더링에서만 쓰입니다. 다시 그릴 때는 무시되고 React가 기억해 둔 값이 나옵니다.
  • state는 컴포넌트가 화면에 놓인 자리마다 따로 있습니다. <Counter />를 두 번 쓰면 두 개가 따로 셉니다.
  • 한 컴포넌트에 여러 개를 쓸 수 있습니다. 서로 관련 없는 값은 따로 둡니다.
const [name, setName] = useState('');
const [age, setAge] = useState(0);
const [isOpen, setIsOpen] = useState(false);
첨부 · 일반 변수로는 왜 안 되나 
function Counter() {
  let count = 0;                       // 다시 그릴 때마다 0 으로 돌아온다

  function handleClick() {
    count = count + 1;                 // 바뀌지만 React 는 모른다
  }
  return <button onClick={handleClick}>{count}</button>;
}

두 가지가 모자랍니다. state는 이 둘을 채웁니다.

첨부 · Hook의 규칙
  1. 최상위에서만 부릅니다. if, for, 중첩 함수 안에서 부르지 않습니다. React는 Hook을 부른 순서로 구분하기 때문에, 렌더링마다 순서가 같아야 합니다.
  2. 컴포넌트 함수 또는 다른 Hook 안에서만 부릅니다. 일반 함수나 이벤트 핸들러 안에서는 부를 수 없습니다.
잘못된 예
if (isLogin) {
  const [name, setName] = useState('');   // 조건에 따라 순서가 달라진다
}

state는 스냅샷이다

2React · state와 이벤트 · 갱신 예약
state는 스냅샷이다
  • 스냅샷: 한 번의 렌더링 안에서 state 값은 고정. set을 불러도 그 자리의 변수는 바뀌지 않음
  • 함수로 갱신: 직전 값을 바탕으로 바꿀 때는 setCount(n => n + 1)처럼 함수를 넘김
세 번 더하기
const [count, setCount] = useState(0) function plusThree() { setCount(count + 1) // 0 + 1 setCount(count + 1) // 0 + 1 setCount(count + 1) // 0 + 1} // 결과: 1 function plusThreeFixed() { setCount(n => n + 1) // 0 → 1 setCount(n => n + 1) // 1 → 2 setCount(n => n + 1) // 2 → 3} // 결과: 3

두 번째 슬라이드는 state를 쓸 때 가장 자주 헷갈리는 부분입니다. 왼쪽 위의 plusThree는 setCount를 세 번 부릅니다. 3이 될 것 같지만 결과는 1입니다.

이유는 count가 이번 렌더링에서 찍어 둔 사진이기 때문입니다. 함수가 불렸을 때 count는 0이었고, 핸들러가 실행되는 동안 계속 0입니다. 그래서 세 줄 모두 "0 더하기 1, 즉 1로 바꿔라"라는 같은 예약을 남깁니다.

setCount는 변수를 그 자리에서 고치는 명령이 아니라, 다음 렌더링에 쓸 값을 예약하는 요청입니다. React는 핸들러가 끝날 때까지 기다렸다가 예약을 모아 한 번만 다시 그립니다. setCount 바로 다음 줄에서 count를 찍어 보면 옛 값이 나오는 것도 같은 이유입니다.

직전 값에 기대어 바꾸고 싶다면 값 대신 함수를 넘깁니다. React는 예약된 함수를 차례로 실행하면서 앞의 결과를 다음 함수의 인자로 넣어 줍니다. 0이 1이 되고, 1이 2가 되고, 2가 3이 됩니다.

첨부 · 객체와 배열 state — 고치지 말고 새로 만든다

React는 state가 앞의 것과 같은 객체인지를 비교해 다시 그릴지 정합니다. 객체의 속성만 고치면 같은 객체이므로 화면이 바뀌지 않습니다. 항상 새 객체나 새 배열을 만들어 넘깁니다.

객체
const [user, setUser] = useState({ name: '서현', age: 20 });

user.age = 21;                          // ✕ 같은 객체를 고쳤다
setUser({ ...user, age: 21 });          // ○ 펼쳐서 복사한 뒤 덮어쓴다
배열
하려는 일쓰지 않는다 (원본을 고침)쓴다 (새 배열을 돌려줌)
추가push, unshift[...items, 새것]
삭제pop, spliceitems.filter(i => i.id !== id)
수정items[0] = …items.map(i => i.id === id ? { ...i, done: true } : i)
정렬sort, reverse[...items].sort() 또는 toSorted()
첨부 · 바로 다음 줄에서 새 값이 필요할 때 
function handleClick() {
  setCount(count + 1);
  console.log(count);        // 아직 옛 값
}

새 값을 변수에 먼저 담아 두고 그 변수를 씁니다.

function handleClick() {
  const next = count + 1;
  setCount(next);
  console.log(next);         // 새 값
}

이벤트 처리

3React · state와 이벤트 · 이벤트 핸들러
이벤트 처리
  • 등록: 요소를 찾아 addEventListener를 부르는 대신, 태그의 onClick 속성에 함수를 넘김
  • 주의: 함수를 넘기는 것이지 호출하는 것이 아님 — onClick={handleClick}
src/SearchForm.jsx
function SearchForm() { function handleSubmit(e) { e.preventDefault() alert('검색합니다') } return ( <form onSubmit={handleSubmit}> <input name="q" /> <button>검색</button> </form> )}

세 번째 슬라이드는 이벤트입니다. Javascript 이벤트 문서에서는 요소를 찾은 뒤 addEventListener로 함수를 등록했습니다. React에서는 요소를 찾을 필요가 없습니다. JSX 태그의 속성에 함수를 넘기면 등록과 해제를 React가 맡습니다.

왼쪽 코드에서 form 태그의 onSubmit에 handleSubmit을 넘겼습니다. 속성 이름은 on 뒤를 대문자로 시작하는 낙타 표기입니다. 이벤트의 종류와 뜻은 Javascript에서 배운 것과 같습니다.

핸들러는 이벤트 객체를 인자로 받습니다. 폼은 제출하면 페이지를 새로 불러오는 것이 브라우저의 기본 동작이므로, preventDefault로 막고 우리가 원하는 일을 합니다. e.target으로 이벤트가 일어난 요소를 얻는 것도 같습니다.

가장 흔한 실수는 함수 이름 뒤에 괄호를 붙이는 것입니다. 괄호를 붙이면 넘기는 것이 아니라 그 자리에서 호출합니다. 화면을 그릴 때마다 실행되고, 그 안에서 state를 바꾸면 다시 그리기가 끝없이 반복됩니다.

인자를 넘겨야 할 때는 화살표 함수로 한 번 감쌉니다. 그러면 누르는 순간에 화살표 함수가 실행되고, 그 안에서 원하는 인자로 함수를 호출합니다.

HTML의 onchange는 입력을 마치고 초점이 떠날 때 일어나지만, React의 onChange는 글자를 칠 때마다 일어납니다(HTML의 oninput에 해당).

이벤트는 DOM과 같이 부모로 전달됩니다. 막으려면 e.stopPropagation()을 부릅니다.

첨부 · state 끌어올리기 — 앞 문서의 삭제 단추 완성

두 컴포넌트가 같은 데이터를 써야 하면, 그 state를 둘의 가장 가까운 공통 부모에 둡니다. 부모는 값을 props로 내려 주고, 바꾸는 함수도 props로 내려 줍니다. 「JSX와 컴포넌트」의 할 일 목록에 state를 넣으면 삭제가 실제로 동작합니다.

import { useState } from 'react';

export default function App() {
  const [items, setItems] = useState([
    { id: 1, text: '우유 사기' },
    { id: 2, text: '산책' },
  ]);

  function handleDelete(id) {
    setItems(items.filter(item => item.id !== id));
  }

  return (
    <>
      <Header count={items.length} />
      <TodoList items={items} onDelete={handleDelete} />
    </>
  );
}

Header와 TodoList는 고칠 필요가 없습니다. items가 바뀌면 App이 다시 그려지고, 새 props를 받은 자식들도 따라 그려집니다.
