Vite가 필요한 이유

1Vite · 시작하기 · 빌드 도구
Vite가 필요한 이유
  • 간격: 우리가 쓰고 싶은 코드(JSX, TypeScript, npm 패키지)와 브라우저가 읽는 코드 사이를 메움
  • 두 가지 일: 개발할 때는 그때그때 변환해 주는 서버, 배포할 때는 최적화된 파일을 만드는 빌드 명령

첫 번째 슬라이드는 Vite가 왜 필요한지입니다. HTML, CSS, Javascript 문서에서는 파일을 저장하고 브라우저로 열면 바로 동작했습니다. 브라우저가 이 세 가지를 직접 읽기 때문입니다.

하지만 요즘 웹 개발에서 쓰는 코드는 브라우저가 그대로 읽지 못합니다. React의 JSX, 타입을 적는 TypeScript, 중첩해서 쓰는 Sass가 그렇습니다. import 뒤에 경로 대신 react처럼 패키지 이름만 적는 것도 브라우저는 이해하지 못합니다. 그 패키지가 어느 폴더에 있는지 모르기 때문입니다.

Vite는 이 간격을 메우는 빌드 도구입니다. 우리가 쓴 코드를 브라우저가 읽는 코드로 바꿔 줍니다. 이름은 프랑스어로 "빠르다"는 뜻이고 "비트"라고 읽습니다.

Vite가 하는 일은 두 가지입니다. 개발하는 동안에는 서버로 떠서, 브라우저가 요청한 파일을 그 자리에서 변환해 돌려줍니다. 배포할 때는 모든 파일을 모아 묶고 크기를 줄여 dist 폴더에 내놓습니다. 이 문서는 개발 서버를, 다음 문서는 설정과 빌드를 다룹니다.

첨부 · Vite란

Vite는 Vue를 만든 에반 유(Evan You)가 2020년에 공개한 빌드 도구입니다. 그전에는 Webpack이 표준처럼 쓰였는데, 프로젝트가 커질수록 개발 서버를 켜는 데 수십 초가 걸렸습니다. Vite는 브라우저가 ES 모듈을 직접 지원하게 된 점을 이용해, 미리 다 묶지 않고 요청받은 파일만 변환하는 방식으로 이 시간을 없앴습니다.

  • 특정 화면 라이브러리에 묶여 있지 않습니다. 플러그인으로 React, Vue, Svelte 등을 지원합니다.
  • React 공식 문서가 Create React App의 대안으로 권하는 빌드 도구 가운데 하나입니다.
  • 설정 없이 시작할 수 있고, 필요할 때 vite.config.js로 조정합니다.
첨부 · 빌드 도구 없이 개발할 수는 없나

가능합니다. 이 사이트(iseohyun.com)도 빌드 도구 없이 HTML · CSS · Javascript 파일을 그대로 올립니다. 다음에 해당하면 빌드 도구가 필요합니다.

  • JSX, TypeScript처럼 변환이 필요한 문법을 쓴다
  • npm 패키지를 import해서 쓴다
  • 파일이 수백 개라 그대로 올리면 요청 수가 너무 많다
  • 배포할 때 압축하고, 파일 이름에 버전(해시)을 자동으로 붙이고 싶다

두 번째 슬라이드는 프로젝트를 만들고 실행하는 방법입니다. Node.js가 설치되어 있다면 터미널에서 첫 번째 명령을 실행합니다. 프로젝트 이름, 쓸 라이브러리, Javascript인지 TypeScript인지를 차례로 묻습니다.

질문에 답하는 대신 두 번째 명령처럼 한 줄로 지정할 수도 있습니다. vanilla는 아무 라이브러리도 쓰지 않는 순수 Javascript 템플릿입니다. Vite 자체를 익히기에는 이것이 가장 단순합니다. React를 쓴다면 react를 고릅니다.

만들어진 폴더로 들어가 npm install로 패키지를 설치합니다. Vite 자신도 이 프로젝트의 패키지로 설치됩니다. 컴퓨터 전체에 설치하는 것이 아니므로 프로젝트마다 다른 버전을 쓸 수 있습니다.

그 뒤로 쓰는 명령은 세 가지뿐입니다. npm run dev는 개발 서버를 띄웁니다. 출력된 주소를 브라우저로 열고 코드를 고치면 됩니다. 끌 때는 터미널에서 Ctrl+C를 누릅니다.

npm run build는 배포할 파일을 dist 폴더에 만듭니다. npm run preview는 그 dist 폴더를 작은 서버로 띄워, 배포하기 전에 빌드 결과가 제대로 동작하는지 확인하게 해 줍니다.

2026-11-18 · npm run 뒤의 이름은 package.json 의 scripts 에 적힌 이름입니다

첨부 · 환경 준비 — Node.js 버전

Vite는 Node.js 위에서 실행됩니다. 설치는 Javascript 기초문법의 「환경2 : Node.js」를 참고합니다. Vite 7 이상은 Node.js 20.19 이상 또는 22.12 이상을 요구하므로, 오래전에 설치했다면 버전을 확인합니다.

node --version
npm --version

Windows PowerShell에서 실행 정책 오류가 날 때: npm 대신 npm.cmd, npx 대신 npx.cmd로 실행합니다.

npm.cmd create vite@latest
npm.cmd run dev

package.json과 package-lock.json은 Git에 올리고, node_modules와 dist는 올리지 않습니다. 템플릿의 .gitignore에 이미 적혀 있습니다.

첨부 · vanilla 템플릿의 폴더 
my-app/
├─ index.html          진입 문서. <script type="module" src="/src/main.js">
├─ package.json
├─ public/             그대로 복사되는 파일
└─ src/

다른 번들러와 달리 index.html이 public 안이 아니라 프로젝트 루트에 있습니다. Vite는 이 HTML을 출발점으로 삼아, 그 안의 <script>와 <link>를 따라가며 필요한 파일을 찾습니다.

개발 서버가 빠른 이유

3Vite · 시작하기 · 개발 서버와 HMR
개발 서버가 빠른 이유
  • 요청할 때 변환: 미리 전부 묶지 않고, 브라우저가 import를 따라 요청한 파일만 변환
  • HMR: 저장하면 바뀐 모듈만 갈아 끼우므로, 새로 고침 없이 화면과 입력 상태가 유지됨

세 번째 슬라이드는 Vite의 개발 서버가 빠른 이유입니다. 왼쪽은 예전 방식입니다. 서버를 켜면 소스 전체와 패키지를 하나로 묶는 작업부터 했고, 그 작업이 끝나야 화면이 열렸습니다. 모듈이 수천 개가 되면 수십 초가 걸렸습니다.

오른쪽의 Vite는 아무것도 묶지 않고 서버를 바로 시작합니다. 브라우저가 index.html을 받아 main.jsx를 요청하면, Vite는 그 파일 하나만 변환해 돌려줍니다. 브라우저는 그 안의 import를 보고 다음 파일을 요청합니다. 브라우저가 ES 모듈을 직접 이해한다는 점을 이용해, 필요한 파일만 필요한 때에 변환하는 것입니다.

다만 node_modules의 패키지는 예외입니다. 패키지 하나가 수백 개의 작은 파일로 이루어진 경우가 많아, 그대로 두면 요청이 수백 번 일어납니다. 그래서 패키지는 처음 한 번만 미리 묶어 캐시에 두고 다시 씁니다.

파일을 저장하면 Vite는 바뀐 모듈만 브라우저로 보내 실행 중인 화면에 갈아 끼웁니다. 이것을 핫 모듈 교체, 줄여서 HMR이라고 합니다. 페이지를 새로 고치지 않으므로 입력해 둔 값이나 열어 둔 창이 그대로 남습니다.

2026-11-18 · 개발 서버는 개발용입니다. 실제 서비스는 빌드한 결과를 올립니다

첨부 · 참조 — 의존성 사전 번들링

개발 서버를 처음 켤 때 Vite는 소스에서 import하는 패키지를 찾아 미리 묶습니다. 결과는 node_modules/.vite에 저장되고, package-lock.json이 바뀌지 않는 한 다시 하지 않습니다.

  • 형식 통일: 오래된 패키지는 ES 모듈이 아닌 CommonJS(require) 형식입니다. 브라우저가 읽을 수 있게 ES 모듈로 바꿉니다.
  • 요청 수 줄이기: 수백 개의 내부 파일로 된 패키지를 파일 하나로 합칩니다.
  • 경로 채우기: from 'react'를 from '/node_modules/.vite/deps/react.js'처럼 브라우저가 찾아갈 수 있는 경로로 바꿉니다.

패키지를 바꿨는데 옛 코드가 계속 나오면 캐시를 무시하고 다시 묶습니다.

npm run dev -- --force
첨부 · 참조 — 브라우저 개발자 도구로 확인하기

개발 서버를 켠 채로 브라우저의 개발자 도구(F12) → 네트워크 탭을 열고 새로 고칩니다.

  • main.jsx, App.jsx가 파일마다 따로 요청됩니다. 묶지 않았다는 증거입니다.
  • App.jsx의 응답을 열어 보면 JSX가 아니라 변환된 Javascript입니다.
  • App.css의 응답도 Javascript입니다. 개발 중에는 CSS를 <style> 태그로 넣어 주는 코드로 바꿔 HMR이 가능하게 합니다.
  • WS(웹소켓) 연결이 하나 있습니다. 파일이 바뀌었다는 소식이 이 연결로 옵니다.
