# 푸시 알림

앱이 정한 때(예: 복습할 때)에 휴대폰이나 PC로 알림을 보냅니다. 알림을 받는 것은 브라우저의 서비스 워커이고, 보내는 것은 서버입니다. 선택 기능이며, 넣을 때는 아래 규칙을 지킵니다.

- 알림이 「조용히」 실패하기 쉬운 기능입니다. 예약이 안 됐는지, 보냈는데 표시가 안 됐는지를 사용자가 알 수 있게 만드는 것이 이 규칙의 중심입니다.
- 아이폰은 홈 화면에 추가한 앱에서만 알림을 받습니다. [「설치」 규칙](#/sh-standard/webapp-common-gui/rules/install.md)을 먼저 적용합니다.

## 구조

```
앱 화면 ──(토큰, 제목, 본문, 보낼 때)──▶ 예약 함수 ──▶ 작업 큐(예약)
                                                          │ 정한 때
                                                          ▼
휴대폰의 서비스 워커 ◀──(데이터 메시지)── FCM ◀── 발송 함수
        │
        ├─ 앱이 뒤에 있음: 서비스 워커가 알림을 띄움
        └─ 앱이 앞에 있음: 열린 화면으로 넘어감 → 화면이 같은 알림을 띄움
```

| 부분 | 하는 일 |
| :--- | :--- |
| 토큰 | 권한을 받은 뒤 서비스 워커 등록과 VAPID 키로 FCM 토큰을 받습니다. 토큰은 기기·브라우저마다 다릅니다. |
| 예약 함수 | 토큰과 보낼 때를 받아 작업 큐에 넣습니다. 응답을 기다리는 시간에 한도(15초)를 둡니다. |
| 작업 큐 | 정한 때에 발송 함수를 부릅니다. 실패하면 다시 부르므로, 주소가 틀리면 같은 작업이 계속 쌓입니다. |
| 발송 함수 | FCM으로 메시지를 보냅니다. 성공하면 메시지 ID를 돌려줍니다. |
| 서비스 워커 | 앱 폴더를 범위로 등록합니다. 범위가 앱의 매니페스트 범위와 같아야 알림이 앱 이름으로 뜹니다. |

## 한 사이트에 앱이 여럿일 때

같은 도메인의 하위 폴더에 알림을 받는 앱이 둘 이상 있으면 **앱마다 Firebase 웹 앱을 따로 등록해 `appId`를 다르게 둡니다.** Firebase 프로젝트, 발신자 ID, VAPID 키, 예약·발송 함수는 함께 써도 됩니다.

- Firebase는 받은 토큰을 도메인 단위 저장소(IndexedDB `firebase-messaging-database`)에 `appId`를 키로 하나만 적어 둡니다.
- `appId`가 같으면 한 앱이 토큰을 받을 때 저장소에서 다른 앱의 기록을 봅니다. 서비스 워커 범위가 달라 기록이 맞지 않으므로, Firebase는 그 토큰을 FCM에서 지우고 새로 받습니다. 두 앱을 번갈아 열 때마다 서로의 토큰이 지워지고, 지워진 토큰으로 예약해 둔 알림은 오지 않습니다.
- 화면의 Firebase 설정과 서비스 워커의 `firebase.initializeApp` 설정에 같은 앱의 `appId`를 씁니다. 한쪽만 바꾸면 토큰을 받는 쪽과 받는 쪽이 다른 앱으로 취급됩니다.
- 새 웹 앱은 Firebase 콘솔의 프로젝트 설정 → 「앱 추가」 → 웹에서 등록합니다. 호스팅 설정은 하지 않아도 됩니다.

## 보내는 형태

**데이터 메시지로만 보냅니다.** 메시지에 `notification` 필드를 넣지 않고, 제목과 본문은 `data`에 문자열로 넣습니다.

| 형태 | 결과 |
| :--- | :--- |
| `notification` 필드 | Firebase가 알림을 직접 띄우고, 서비스 워커도 하나를 더 띄워 **같은 알림이 2개** 뜹니다. 아이콘과 묶음을 정할 수 없습니다. |
| `data`만 | 알림은 앱(서비스 워커 또는 열린 화면)만 띄웁니다. 아이콘, 묶음, 문구를 앱이 정합니다. |

```js
// 발송 함수
const message = {
  data: { title: String(title), body: String(body) },
  webpush: { headers: { Urgency: 'high' } },
  token,
};
```

## 띄우는 모양

서비스 워커와 열린 화면이 **같은 모양**으로 띄웁니다.

| 항목 | 값 |
| :--- | :--- |
| 아이콘 | 서비스 워커 범위 기준의 `icon-192.png` 절대 주소 |
| 묶음 | 기능마다 고정된 `tag`(예: `review-reminder`). 같은 알림이 여러 번 와도 하나로 바뀝니다. |
| 다시 울림 | `renotify: true`. 바뀐 알림도 소리와 진동을 냅니다. |
| 누르면 | 열린 앱 창이 있으면 그 창으로, 없으면 서비스 워커 범위 주소를 엽니다. |

## 앱이 열려 있을 때

앱이 화면에 떠 있으면 Firebase는 알림을 띄우지 않고 메시지를 그 화면으로 넘깁니다. 화면에 받는 처리기가 없으면 **메시지가 그대로 버려집니다.**

- 토큰을 받은 직후 `onMessage`를 한 번만 걸고, 받은 메시지를 서비스 워커와 같은 모양의 알림으로 띄웁니다.
- 앱 안에 띠로만 알리는 방식도 되지만, 사용자가 화면을 보고 있지 않을 수 있으므로 시스템 알림을 띄웁니다.

## 예약하는 때

| 항목 | 규칙 |
| :--- | :--- |
| 다른 저장과의 순서 | 예약은 다른 저장(진도·기록 저장)을 기다리지 않고 먼저 시작합니다. 저장이 멈추면 예약도 같이 멈추기 때문입니다. |
| 권한 묻기 | 사용자가 누른 버튼 안에서만 묻습니다. 앱을 열자마자 묻는 요청은 Chrome이 조용히 막고, 아이폰은 사용자 동작 밖에서 물을 수 없습니다. |
| 앱을 열 때 | 이미 허용된 경우에만 토큰을 조용히 받아 둡니다. |
| 결과 기록 | 마지막 예약 결과(성공이면 보낼 때, 실패면 까닭)를 저장소에 남깁니다. 까닭은 토큰 받기 실패, 서버 오류, 연결 실패로 나눕니다. |

## 설정 화면

[「전체 설정」](#/sh-standard/webapp-common-gui/rules/settings.md)에 한 줄을 둡니다.

| 요소 | 동작 |
| :--- | :--- |
| 켜고 끄기 | 알림을 받을지 고르는 스위치. 기본은 켬. 끄면 예약을 보내지 않습니다. |
| 상태 글 | 받음, 받지 않음, 권한이 필요함, 차단됨, 이 기기에서 쓸 수 없음 |
| 권한 허용 단추 | 켜져 있고 권한이 아직 없거나 실패했을 때만 보입니다. 켜는 순간에 권한이 없으면 같은 동작 안에서 바로 묻습니다. |
| 마지막 예약 | 「마지막 예약: 14:40 알림 예정」 또는 빨간 글씨의 「마지막 예약 실패 (14:29) · 예약 서버에 연결하지 못함」 |

## 확인하는 법

| 확인 | 방법 |
| :--- | :--- |
| 예약이 서버에 닿았나 | 예약 함수의 요청 로그에 기기의 요청이 200으로 남았는지 봅니다. |
| 보냈나 | 작업 큐에서 발송 함수를 부른 기록이 200인지 봅니다. 큐에 작업이 남아 재시도 수가 늘면 발송 주소가 틀린 것입니다. |
| 기기에 왔나 | 안드로이드는 무선 디버깅으로 `dumpsys activity service com.google.android.gms/.gcm.GcmService`의 수신 기록을 봅니다. 메시지 ID 앞부분이 보낸 시각(마이크로초)입니다. |
| 떴나 | `dumpsys notification --noredact`에서 알림을 띄운 패키지와 `tag`를 봅니다. 설치한 앱이면 `org.chromium.webapk.…` 패키지입니다. |
| 두 경우 모두 | 앱을 뒤로 보낸 상태와 앞에 띄운 상태에서 각각 한 번씩 보내, 둘 다 알림이 **하나씩** 뜨는지 봅니다. |

- 설치한 앱을 여는 동안 Chrome이 띄우는 「(앱 이름) · 탭하여 이 앱의 URL 복사하기」 알림은 Chrome 이름과 아이콘으로 뜹니다. 앱이 보낸 알림이 아닙니다.
- 휴대폰 Chrome이 구글 주소(`googleapis.com`)를 찾지 못하면 토큰을 받지 못해 예약이 시작되지도 않습니다. 설정 화면의 「마지막 예약 실패」로 드러납니다.

> 참조: CharQuiz에서 복습 알림이 오지 않던 문제를 고치며 정했습니다. 발송 주소의 지역이 큐의 지역(asia-northeast3)으로 잘못 만들어져 작업이 쌓였고, 저장이 멈추면 예약도 멈췄고, `notification` 형태로 보내 알림이 2개 뜨거나 앱이 열려 있으면 사라졌습니다. 같은 도메인의 NameQuiz에 알림을 넣을 때 CharQuiz와 `appId`가 같아 토큰을 서로 지우게 되는 것을 찾아, NameQuiz용 웹 앱을 따로 등록했습니다.

## 서버 쪽 주의

| 항목 | 규칙 |
| :--- | :--- |
| 함수와 큐의 지역 | 큐의 지역과 함수가 배포된 지역을 따로 둡니다. 발송 주소는 함수의 지역으로 만듭니다. |
| 함수를 고친 뒤 | 앱 판과 별도로 함수를 배포해야 반영됩니다. 이미 큐에 들어간 작업은 옛 주소를 그대로 씁니다. |
| 막힌 작업 | 주소를 고친 뒤에도 옛 작업은 계속 실패하므로 큐에서 지웁니다. |

## 아직 확정하지 않은 값

| 항목 | 임시 결정 |
| :--- | :--- |
| 기본에 넣을지 | 넣지 않음. 알림이 필요한 앱만 |
| 앱이 열려 있을 때 | 시스템 알림을 그대로 띄움 |
| 알림 끄기의 기본값 | 켬 |
