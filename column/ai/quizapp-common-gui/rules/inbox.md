# 알림함

휴대폰 알림은 한 번 넘기면 사라지므로, 받은 **복습 알림**을 앱 안에 모아 둡니다. 알림을 보내는 쪽 규칙은 WebApp Common GUI [「푸시 알림」](#/column/ai/webapp-common-gui/rules/push.md)에 있습니다.

## 저장

| 항목 | 값 |
| :--- | :--- |
| 저장소 | 기기의 IndexedDB `{앱}-inbox`(`charquiz-inbox`, `namequiz-inbox`), 저장소 `items`, 키 `id` 자동 증가 |
| 항목 | `{ title, body, receivedAt, read: false }` |
| 개수 | 최대 50개. 넘으면 오래된 것부터 지웁니다. |
| 들어오는 것 | 받은 복습 알림만 |

- 기기에만 두고 서버에 올리지 않습니다. 다른 기기의 알림함과는 따로입니다.

## 들어오는 길

| 앱의 상태 | 누가 적나 |
| :--- | :--- |
| 뒤에 있음 | 서비스 워커(`firebase-messaging-sw.js`)가 알림을 띄우며 같은 DB에 적고, 열린 창에 `{앱}-inbox-updated` 메시지를 보냅니다. |
| 앞에 있음 | 화면의 `onMessage`가 알림함에 적은 뒤 알림을 띄웁니다. |
| 알림을 누름 | 열린 창이 있으면 `{앱}-open-inbox` 메시지로, 없으면 `?inbox=1`을 붙여 앱을 열어 알림함을 띄웁니다. |

- DB 이름과 메시지 이름은 화면(`notification-inbox.js`)과 서비스 워커 양쪽에 같게 적습니다. 한쪽만 바꾸면 알림이 쌓이지 않습니다.

## 창

| 요소 | 내용 |
| :--- | :--- |
| 제목 | 「🔔 알림함」 |
| 항목 | 제목, 본문, 받은 때(오늘이면 「오늘 HH:MM」, 아니면 「M/D HH:MM」) |
| 빈 목록 | 「받은 알림이 없어요. 학습을 마치면 복습할 때를 알려 드려요.」 |
| 지금 복습하기 | 문제를 풀고 있지 않을 때 학습 모드를 바로 시작합니다. |
| 모두 지우기 | 「알림함을 모두 비울까요?」로 확인한 뒤 비웁니다. |
| 읽음 | **창을 열면 모두 읽음**으로 바꿉니다. 하나씩 읽음 처리는 하지 않습니다. |

## 읽지 않은 수 배지

| 항목 | 규칙 |
| :--- | :--- |
| 자리 | 알림함 종 단추 위(기본: 설정 창 머리의 종. NameQuiz는 헤더의 종) |
| 숫자 | 읽지 않은 항목 수. 0이면 숨김. 99를 넘으면 「99+」(NameQuiz는 9를 넘으면 「9+」) |
| 고치는 때 | 앱을 열 때, 서비스 워커 메시지를 받을 때, 화면이 다시 보일 때(`visibilitychange`), 항목을 더한 뒤 |
| 알리기 | 수가 바뀌면 `{앱}-inbox-changed` 이벤트(`detail.unread`)를 보내 new 점이 따라 바뀌게 합니다. |

## 설정 톱니의 new 점

알림함이 설정 창 안에 있으므로, 헤더에서 보이도록 설정 톱니에 작은 점을 찍습니다(`components/new-dot.js`).

| 켜지는 까닭 | 꺼지는 때 |
| :--- | :--- |
| 새 판: `window.APP_VERSION`(정식 판, 예 `v1.0.5`)이 기기의 `{앱}_SEEN_VERSION`과 다름 | 설정 창을 열면 지금 판을 「본 판」으로 적어 둡니다. |
| 읽지 않은 알림이 1개 이상 | 알림함을 열어 모두 읽음이 되면 |

- 둘 중 하나라도 해당하면 켭니다.
- 비교 기준은 캐시 버스팅 표시(`CACHE_BUST`)가 아니라 **정식 판**입니다. 작은 배포마다 점이 뜨지 않게 하기 위해서입니다. 배포마다의 새로 고침 안내는 WebApp Common GUI의 업데이트 알림 띠가 맡습니다.
- 처음 연 기기(본 판 기록이 없음)는 지금 판을 적어 두고 점을 켜지 않습니다.
- 설정 창 안의 「앱 정보·도움말(i)」 단추에도 같은 점을 찍습니다. 설정을 연 그때 새 판이었으면 그 창이 떠 있는 동안만 보입니다(본 판으로 적기 전에 계산).
