# 판 이력

Common GUI가 바뀔 때마다 바뀐 항목을 한 줄씩 적고 항목 ID를 붙입니다. 앱은 자기가 어느 판까지 확인했는지 기록해 두고, 그보다 새 판의 항목만 하나씩 골라 받습니다.

- 앱에 적용하지 않기로 한 항목이 있어도, 확인을 마치면 앱의 기록 판은 지금 판으로 올립니다. 다음에는 그 뒤의 새 항목만 묻습니다.
- 확인하지 않은 판의 항목만 묻기 때문에, 몇 판을 건너뛰어도 한 번에 비교할 수 있습니다.

## 앱이 새 판을 받아 가는 법

1. 앱의 `.agents/rules/common-gui.md`에서 「확인한 판」과 항목별 결정을 읽습니다. 파일이 없으면 기준 판부터 정합니다.
2. 이 문서의 「바뀐 항목」에서 확인한 판보다 새 판의 항목을 고릅니다. 이미 결정이 적힌 항목은 빼고, 「보류」로 적힌 항목은 다시 넣습니다.
3. 항목마다 「적용」, 「적용 안 함」, 「보류」 중 하나를 사용자에게 묻습니다. 앱에 그 기능의 바탕이 없으면(슬라이드가 없는 앱의 `slide-keys`) 「해당 없음」을 먼저 제안합니다.
4. 「적용」한 항목은 링크된 규칙대로 앱을 고치고 동작을 확인합니다.
5. 「확인한 판」을 지금 판으로 올리고, 항목마다 결정과 날짜를 적습니다. 적용하지 않은 항목이 있어도 판은 올립니다.

## 앱 쪽 기록

각 앱의 `.agents/rules/common-gui.md`에 둡니다.

```markdown
# WebApp Common GUI 동기화 기록

- 확인한 판: v0.5.6 (2026-11-18)
- 화면 틀: 씀 | 쓰지 않음 (쓰지 않으면 화면 틀에 딸린 항목은 「해당 없음」이 기본)

| 항목 ID | 판 | 결정 | 날짜 | 메모 |
| :--- | :--- | :--- | :--- | :--- |
| install | v0.5.6 | 적용 | 2026-11-18 | |
| update-notice | v0.5.6 | 적용 안 함 | 2026-11-18 | 배포가 드묾 |
```

| 결정 | 뜻 | 다음 확인 때 |
| :--- | :--- | :--- |
| 적용 | 앱에 넣었음 | 묻지 않음 |
| 적용 안 함 | 보고 나서 넣지 않기로 함 | 묻지 않음. 마음이 바뀌면 사용자가 따로 요청 |
| 해당 없음 | 앱에 그 기능의 바탕이 없음 | 묻지 않음 |
| 보류 | 지금 정하지 않음 | 다시 물음 |

- 확인한 판보다 새 판의 항목을 먼저 적용했다면(판을 거치지 않고 한 기능만 가져온 경우) 그 항목만 「적용」으로 적고 확인한 판은 그대로 둡니다.

## 판을 올리는 규칙

| 항목 | 규칙 |
| :--- | :--- |
| 언제 | 규칙의 동작이 바뀔 때. 앱이 무언가를 고쳐야 받을 수 있는 변경이면 판을 올립니다. |
| 누가 | 규칙을 고친 AI가 다음 판 번호를 제안하고 사용자가 승인합니다. 승인 전에는 판 칸에 「다음 판(미정)」이라고 적습니다. |
| 묶음 | 같은 날의 변경은 한 판에 묶습니다. |
| 번호 | 끝자리를 하나 올립니다. 화면 틀의 모양이 크게 바뀌면 가운데 자리를 올립니다. |
| 항목 ID | 영어 소문자와 붙임표. 한 번 정하면 바꾸지 않습니다. 같은 기능을 다시 고치면 새 ID(`update-notice-2`)를 씁니다. |
| 문서 머리 | 각 규칙 문서 머리의 「판」은 그 문서가 마지막으로 바뀐 판입니다. |
