# 구조

프로젝트는 서버 없는 웹앱으로 시작합니다. 계산이 무거워져 성능을 올려야 할 때는 beep-gen이 간 길을 따릅니다. 화면은 그대로 두고, 계산만 떼어 내 더 빠른 곳에서 돌립니다.

- **기본**: 브라우저 안에서 모든 것을 처리하는 웹앱. 정적 호스팅에 올리고 서버를 두지 않습니다.
- **성능이 필요할 때**: 화면 1벌, 코어 1벌, 환경마다 어댑터만 바꿉니다.
- 단계를 건너뛰지 않습니다. 필요가 생긴 만큼만 올라갑니다.

> beep-gen의 이 구조는 `main`이 아니라 작업 브랜치(`claude/beep-gen-multi-platform-…`)에 있고, 그 브랜치의 `.agents/rules/project_architecture.md`에 적힌 규칙을 일반화했습니다. `main`의 beep-gen은 아직 Python + PyQt6 프로그램입니다.

## 단계

아래로 갈수록 빠르고 할 수 있는 일이 늘지만, 만들고 유지할 것도 늘어납니다. 「올라가는 신호」가 보일 때만 다음 단계로 갑니다.

| 단계 | 모습 | 계산이 도는 곳 | 다음 단계로 올라가는 신호 |
| :--- | :--- | :--- | :--- |
| **0. 웹앱** | 화면과 계산이 한 곳에 있는 보통의 웹앱. 이 문서의 기본 화면이 여기입니다. | 화면과 같은 곳 | 계산하는 동안 화면이 멈칫한다. 누르거나 스크롤해도 반응이 늦다. |
| **1. 워커** | 계산을 함수 묶음으로 떼어 내 워커로 옮깁니다. 언어는 그대로입니다. | 브라우저의 워커 | 워커에서 돌려도 수 초 넘게 걸린다. 메모리를 많이 쓴다. 같은 계산을 브라우저 밖에서도 써야 한다. |
| **2. 코어** | 계산을 Rust 코어로 다시 쓰고 WASM으로 만들어 워커에서 돌립니다. | 워커 안의 WASM | 브라우저가 막는 일이 필요하다. 예: 다른 사이트의 파일 받기, 기기에 깔린 음성 쓰기, 큰 파일 다루기. |
| **3. 로컬앱** | 같은 화면을 Tauri로 감쌉니다. 코어는 WASM 대신 기기용으로 컴파일한 것을 씁니다. | 기기에서 직접 | 화면 없이 돌려야 한다. 다른 프로그램이나 AI가 불러 써야 한다. |
| **4. 명령줄 · MCP** | 같은 코어와 같은 절차를 명령줄 도구와 로컬 MCP로 엽니다. | 기기에서 직접 |  |

beep-gen은 0에서 바로 2로 갔습니다. 1단계는 그 사이에 둔 중간 단계입니다. 화면 멈춤만 문제라면 언어를 바꾸지 않고도 풀리기 때문에, 코어를 다시 쓰는 일은 그것으로 모자랄 때까지 미룹니다. 코어는 Rust, 로컬앱은 Tauri로 정했고, 화면 쪽 기술은 프로젝트가 고릅니다.

## 견본: 화면에서와 워커에서

같은 계산(정해진 수까지 소수 세기)을 두 곳에서 돌려 봅니다. 오른쪽의 숫자는 화면이 살아 있는 동안 계속 올라갑니다. 화면에서 돌리면 계산이 끝날 때까지 숫자가 멈추고, 워커에서 돌리면 멈추지 않고 진행 상황도 나옵니다.

## 세 층

| 층 | 하는 일 | 하지 않는 일 |
| :--- | :--- | :--- |
| 화면 | 입력을 받고 결과를 보여 줌. 플랫폼 창구의 함수만 부름. | 웹인지 로컬앱인지 묻지 않음. 계산하지 않음. |
| 플랫폼 창구 | 화면이 아는 유일한 약속. 함수의 모양과 주고받는 자료의 모양을 정함. | 구현을 담지 않음. |
| 어댑터 | 환경마다 다른 일: 자료 가져오기, 결과 내보내기, 기기 기능 부르기. | 자료의 내용을 건드리지 않음. 계산은 전부 코어에 넘김. |
| 코어 | 계산 전부. 입력 항목의 이름·기본값·범위의 정의. 결과에 붙일 보고와 경고. | 파일, 네트워크, 시계, 운영체제를 직접 쓰지 않음. |

## 지킬 규칙

| 규칙 | 내용 | 지키는 방법 |
| :--- | :--- | :--- |
| 코어에 환경 코드 금지 | 코어는 파일, 네트워크, 시계, 운영체제 호출을 쓰지 않습니다. | 자동 검사에서 코어를 항상 WASM으로도 빌드합니다. 환경 코드가 섞이면 여기서 깨집니다. |
| 어댑터에 계산 금지 | 어댑터는 가져오기, 내보내기, 기기 호출만 합니다. | 자료의 내용을 바꾸는 코드가 어댑터에 보이면 코어로 옮깁니다. |
| 환경 이름으로 가르지 않기 | 「로컬앱이면」이 아니라 「주소로 받기를 지원하면」으로 판단합니다. | 환경을 확인하는 코드는 시작할 때 어댑터를 고르는 한 곳에만 둡니다. 화면은 기능 목록만 봅니다. |
| 입력 항목의 정의는 한 곳 | 항목의 이름, 기본값, 범위, 단위를 코어 한 곳에 적습니다. | 화면의 입력 폼, 명령줄 옵션, MCP 도구의 입력 명세를 모두 거기서 만들어 냅니다. 항목을 더하면 세 곳에 함께 나타납니다. |
| 일의 순서도 한 곳 | 「가져오기 → 준비하기 → 코어 부르기」 같은 순서를 한 함수에 둡니다. | 로컬앱, 명령줄, MCP가 그 함수만 부릅니다. |
| 코어는 어디서나 컴파일되게 | WASM 빌드를 깨는 의존성(C/C++ 라이브러리, 시스템 프로그램)을 코어에 넣지 않습니다. | 순수 Rust 라이브러리만 씁니다. 로컬 어댑터는 이 제한을 받지 않습니다. |
| 결과 비교는 특성으로 | 웹과 로컬의 결과가 한 값 한 값 똑같지 않을 수 있습니다. | 길이, 위치, 검출값 같은 특성으로 비교합니다. 양쪽 결과가 달라지지 않게 수학 함수는 한 라이브러리로 통일합니다. |
| 실패해도 할 수 있는 만큼 | 곁가지 기능이 실패해도 본래 결과는 만듭니다. | 결과에 「알릴 일」 목록을 붙여 화면이 사용자에게 보여 줍니다. |

## 주고받는 약속

### 플랫폼 창구

```text
Platform
├─ capabilities              이 환경에서 되는 기능의 목록 (참 / 거짓)
├─ describe()                화면 구성 정보: 버전 · 입력 항목 명세 · 결과 형식
├─ run(요청, 진행 알림)      실행하고 결과를 돌려줌. 진행 알림은 { 백분율, 단계 설명 }
└─ save(결과)                결과를 사용자의 기기에 저장. 취소하면 거짓

입력 항목 명세 (코어가 정의)
└─ key · label · description · unit · kind · default · min · max · step · choices · advanced · when

결과
└─ 내용 · 파일 이름 · 형식 · 보고(있을 때) · 알릴 일 목록
```

### 화면과 워커 사이

```text
화면 → 워커     { id, type: "describe" }
                { id, type: "run", 입력값(JSON), 큰 자료(ArrayBuffer) }
워커 → 화면     { id, type: "described", 정보(JSON) }
                { id, type: "progress", percent, stage }
                { id, type: "done", 결과 }
                { id, type: "error", message }
```

- 요청마다 번호(`id`)를 붙이고, 답에 같은 번호를 실어 짝을 맞춥니다.
- 큰 자료는 복사하지 않고 넘겨줍니다. 설정값처럼 작은 것은 JSON 글자로 보냅니다.
- 긴 계산은 구간으로 나눠 처리하고 구간마다 진행 상황을 보냅니다. 결과 전체를 메모리에 쌓지 않습니다.
- 오류는 던지지 않고 `error` 메시지로 돌려보냅니다. 화면은 사람이 읽을 수 있는 문장을 그대로 보여 줍니다.

## 폴더와 빌드

```text
apps/
  web/                       화면 (0단계부터 있음)
    src/platform.ts          플랫폼 창구 (1단계부터)
    src/platform-web.ts      웹 어댑터
    src/worker.ts            워커
    src/worker-protocol.ts   화면과 워커가 주고받는 메시지
    src/wasm/                코어를 WASM으로 만든 것 (2단계, 저장소에 올리지 않음)
    src/platform-desktop.ts  로컬 어댑터의 화면 쪽 (3단계)
    src/version.ts           정식 버전 · 빌드 표시
  desktop/src-tauri/         로컬앱 껍데기 (3단계). 화면 코드는 따로 두지 않음
crates/
  이름-core/                 코어 (2단계)
  이름-wasm/                 코어를 브라우저에 잇는 얇은 층 (2단계)
  이름-native/               로컬 어댑터와 공용 절차 (3단계)
  이름-cli/                  명령줄과 MCP (4단계)
```

| 항목 | 규칙 |
| :--- | :--- |
| 호스팅 | 정적 호스팅만 씁니다. 서버를 두지 않습니다. |
| 경로 | 상대 경로로 빌드합니다. 주소의 하위 폴더가 달라도 같은 결과물이 동작해야 합니다. |
| 로컬앱의 화면 | 웹의 빌드 결과물을 그대로 담습니다. |
| 버전 | 화면의 버전과 코어의 버전이 다르면 빌드를 실패시킵니다. |
| 오프라인 | 기본에는 넣지 않고 필요한 프로젝트만 넣습니다. 넣을 때는 서비스 워커의 캐시 이름에 빌드 표시를 써서, 빌드 표시가 바뀌면 새 파일을 받게 합니다. |
| 설치 | 매니페스트와 아이콘을 넣어 홈 화면에 설치할 수 있게 합니다. 규칙은 [「설치」 규칙](#/column/ai/webapp-common-gui/rules/install.md). |
| 커밋 전 확인 | 웹 빌드와 코어의 시험이 모두 통과해야 합니다. |
| MCP | 기기에서 실행하는 방식만 씁니다. 파일을 쓸 때는 절대 경로만 받고, 있는 파일은 명시적으로 허락해야 덮어씁니다. |

## 기본 화면과 만나는 곳

| 구조 쪽 | 기본 화면 쪽 |
| :--- | :--- |
| 기능 목록 | 지원하지 않는 기능의 버튼과 설정 항목을 숨깁니다. 꺼진 채로 두지 않습니다. |
| 입력 항목 명세 | 필터와 설정의 줄을 명세에서 그립니다. 항목 이름이 왼쪽, 컨트롤이 오른쪽인 같은 줄 모양입니다. |
| 진행 알림 | 실행 버튼 옆에 진행 막대와 단계 설명 한 줄을 둡니다. |
| 알릴 일 목록 | 결과 아래에 한 줄씩 보여 줍니다. |
| 오류 | 본문 영역의 오류 경계와 같은 모양으로, 무엇이 잘못됐는지와 다시 시도 버튼을 보여 줍니다. |
| 버전 | 패널 하단과 문서 정보에 화면 버전과 코어 버전을 함께 적습니다. |

## 확정한 값

| 항목 | 결정 |
| :--- | :--- |
| 기본 | 서버 없는 웹앱 |
| 1단계(워커) | 둔다. 화면 멈춤만 문제면 언어를 바꾸지 않고 워커로 옮기는 데서 끝냄 |
| 코어의 언어 | Rust. 웹에서는 WASM으로 만들어 씀 |
| 로컬앱의 틀 | Tauri |
| 화면 쪽 기술 | 고정하지 않음. 플랫폼 창구의 약속만 지킴 |
| 오프라인 지원 | 기본에 넣지 않고 필요한 프로젝트만 |
| 플랫폼 창구를 만드는 때 | 계산을 떼어 내는 시점(1단계) |
