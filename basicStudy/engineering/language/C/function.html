첫 번째 슬라이드는 함수가 호출될 때 프로그램의 실행 줄이 어떻게 이동하고 복귀하는지 직접 눈으로 확인할 수 있는 시뮬레이터입니다. 맨 위 1행의 프로토타입 선언은 위에서 아래로 코드를 읽는 C 컴파일러에게 뒤에 등장할 Max 함수의 반환형과 인자 개형을 미리 등록해 주는 시제품 선언이며, 보통 헤더(.h) 파일에 모아 둡니다.

실제 프로그램 실행은 언제나 2행 main 함수부터 출발합니다. 3행에서 지역변수 x에 3, y에 7을 준비한 뒤 4행에서 Max(x, y)를 만나는 순간 함수 호출이 일어납니다.

4행에서 호출이 일어나면 CPU는 나중에 돌아올 위치(4행)를 기억해 둔 채, 전달인자(Argument) 3과 7을 복사해 들고 8행의 Max 함수 정의 위치로 실행 줄을 곧장 점프시킵니다. 이때 Max 입장에서 전달받는 변수 a와 b를 매개변수(Parameter)라고 부릅니다.

이어서 9행 함수 본체(Body)에서 두 값을 비교해 더 큰 값 7을 지역변수 m에 저장합니다. 참고로 C++에서는 함수 이름이 같더라도 매개변수의 개수나 타입이 다르면 서로 다른 함수로 구분해 호출해 주는 오버로딩을 지원하지만, 반환형만 다른 것은 구분 기준이 되지 않습니다.

10행에서 return m을 수행하는 즉시 Max 함수의 실행은 종료되고, Max 안에서 쓰던 지역변수 메모리는 회수되며 결과값 7만 들고 아까 호출했던 4행 대입식 자리로 정확히 복귀합니다.

복귀한 뒤에는 res에 7을 대입하고 그 다음 줄인 5행 printf로 자연스럽게 내려가 출력을 마칩니다. 오른쪽 위의 실행 단추나 각 코드 줄을 직접 눌러 실행 흐름이 점프했다가 돌아오는 모습을 확인해 보세요.

* 함수가 호출되기 위해서는 반드시 '정의'가 되어있어야 합니다. '선언'되었다는 표현은 일반적으로 맞을 수 있지만, 엄밀하게 말하면 등록하는 과정을 의미하므로, 수동으로 등록하는 과정을 거친다면(옵션), 두 과정(정의와 선언)을 혼돈해서는 안 될 것입니다.

첨부 · 문법 (Syntax)
함수를 정의 할 때
[리턴형] 함수이름([전달인자]) {
  내용;
  return [리턴 변수];
}
함수를 호출 할 때
[리턴 받을 변수] = 함수이름([전달인자]);
예시
int Max(int a, int b){
  int max = (a > b)?a:b;
  return max;
}

함수는 기능을 하나로 묶어서 호출이 되었을 때, 기술된 내용을 수행합니다.

  • 전달인자(Argument)는 여러개이거나 생략될 수 있습니다.
  • 전달인자는 넘겨주는 타입과 순서가 중요합니다.
  • 리턴(return)은 한개 또는 생략만 가능합니다.
  • 리턴을 생략할 땐, void를 명시해야 합니다.
    void setName(char[] name) { ... }
  • 리턴이 수행되면, 그 행에서 함수가 종료되고, 호출한 함수로 돌아갑니다.
첨부 · 참조 — 프로토타입과 헤더 (Prototype & Header)

프로토타입 (Prototype)

근래의 언어는 컴파일러가 명시된 모든 엘리먼트를 1차적으로 리스트업합니다. 반면, C언어는 코드를 위에서부터 순차적으로 파싱(parsing; 해석)하기 때문에, 뒤에 어떠한 내용이 등장 할 것이라고 미리 알려주는 작업을 수행하여야 합니다. 프로토타입(prototype; 시제품)은 함수의 개형 정보를 컴파일러에게 전달하는 역할을 합니다.
함수의 바디(body; 내용)을 작성하지 않고 세미콜론(;)으로 마무리하면 됩니다. 함수의 정의가 존재해야 합니다.

프로토타입 문법
[반환형] [함수명]([전달인자]...);
예시
int max(int a, int b);

헤더 (Header)

함수의 프로토타입을 선언하면, 실제 함수의 정의가 반드시 존재해야 합니다. 하지만 반드시 같은 파일이나 내가 작성한 파일에 존재해야 하는 것은 아닙니다. 프로토타입의 정보는 코딩에 대한 본질적인 내용이 아니고, 컴파일에 필요한 메타 정보 입니다. 이를 header라고 하고, .h라는 확장자를 사용합니다. 그리고 이 헤더를 불러올 때는 #include 예약어를 사용합니다.

헤더파일 예시
#include <stdio.h>

stdio(StanDard Input / Output)는 입출력과 관련된 함수를 가지고 있습니다. 따라서 stdio.h에는 다음과 같은 내용을 확인 할 수 있습니다(minGW64기준입니다).

stdio.h 발췌
int printf (const char *__format, ...)

문제 해결 (undefined reference to ~)

여러 파일로 나뉜 코드를 단일 파일 방식으로 빌드하려고 할 때 링크 오류가 발생할 수 있습니다. 파일 하나를 컴파일 할 때 명령어는:

gcc -o execute_file foo.cpp

이 명령어를 수행하면 execute_file.exe파일이 생성됩니다.
만약 추가로 컴파일이 필요한 파일을 함께 묶으려면:

gcc -o execute_file foo.cpp bar.cpp

해당 폴더에 포함된 모든 cpp파일을 추가하려고 하면 다음과 같이 작성할 수 있습니다.

gcc -o execute_file *.cpp

두 번째 슬라이드는 콜 스택 메모리를 실제 16진수(HEX) 바이트 단위로 들여다보는 시뮬레이터입니다. 오른쪽 표의 1열은 메모리 주소 헤더이고, 2~5열과 7~10열은 각각 4바이트(int 1개 크기)씩 총 8바이트를 나타냅니다. 아직 쓰이지 않은 빈 스택 공간에는 0이 아니라 알 수 없는 랜덤 HEX 값들이 가득 차 있습니다.

12행에서 int x = 10;을 실행하면 0x1044부터 4바이트 칸에 10의 16진수 값인 00 00 00 0A가 기록되며 노란색으로 하이라이트됩니다.

이어서 func1(x)가 호출되면 스택 포인터(SP)가 아래(높은 주소)에서 위(낮은 주소 0x1030)로 올라가며, 복귀 주소와 매개변수 a=0A, 그리고 지역변수 key = 0xABCD8765(AB CD 87 65)와 tmp = 15(00 00 00 0F)가 실제 메모리에 그대로 기록됩니다.

핵심은 func1이 반환된 직후입니다. SP만 다시 0x1040으로 내려올 뿐, 방금 쓰던 0x1030~0x103F 메모리의 AB CD 87 65 데이터는 지워지지 않고 그대로 남아 있습니다.

그다음 14행에서 func2(1)을 호출하면 아까 func1이 쓰던 바로 그 0x1030 번지에 새 프레임이 들어오면서, 남아 있던 AB CD 87 65 위에 CA FE 00 01을 그대로 덮어씁니다.

이후 탈출 조건 없는 재귀 호출로 func2(2), func2(3)이 위로 차오르다가, func2(4)에서 스택 한계선(0x1010)을 넘어가 버립니다. 이때 운영체제(OS)가 메모리 보호로 개입하지 않는 환경이라면 프로그램이 곧바로 강제 종료되지도 않은 채, 위쪽 인접 영역의 기존 데이터(11 22 33 44, DE AD BE EF)를 스택 값으로 덮어써 조용히 오염시킵니다.

첨부 · 오버로딩 (Overloading)

함수 오버로딩(overloading)의 목적은 비슷한 기능을 하는 여러개의 함수를 하나의 함수명으로 관리함으로써 개발자의 개발 부담을 줄여주는 효과가 있습니다.

함수를 구분하는 기준은 "함수명+전달인자 갯수/타입"입니다 (리턴인자는 함수를 구분하는데 영향을 주지 않습니다). 함수를 구분한다는 의미는, 컴파일러가 함수가 호출되었을 때, 어떤 함수를 호출할지 결정하는데 참고하겠다는 의미입니다. 예를들어: 

void setVariable(int height);            // function 1

void setVariable(float height);          // function 2 (타입 다름: 가능)

void setVariable(int width);             // function 3 (인자명만 다름: 오류)

int setVariable(int height);             // function 4 (리턴형만 다름: 오류)

void setVariable(int height, int width); // function 5 (개수 다름: 가능)
  • function 1 vs 2 : 전달인자의 타입이 다르므로 둘은 서로 다른 함수로 인식
  • function 1 vs 3 : 전달인자의 인자명은 함수를 구분하는 기준이 아니므로 둘은 서로 같은 함수(컴파일러 오류)
  • function 1 vs 4 : 리턴인자의 타입은 함수를 구분하는 기준이 아니므로 둘은 서로 같은 함수(컴파일러 오류)
  • function 1 vs 5 : 전달인자의 갯수가 각각 1, 2개로 서로 다르므로 서로 다른 함수로 인식
첨부 · 콜 스택 (Call Stack)

함수를 호출(call)했을 때, CPU는 할당받은 메모리 영역에 현재의 수행위치와 전달인자를 저장해두고, 함수의 수행위치를 호출된 함수로 변경하게 됩니다.
스택(stack)은 선입후출의 저장 알고리즘입니다. 저장공간이 무한하지 않기 때문에, 함수가 반환되지 않고 계속해서 호출된다면 스택 오버플로우(overflow; 넘침)가 발생하게 됩니다. 스택 오버플로우는 syntax error(문법 에러)가 아니고 run time error(수행 중 에러)이기 때문에 예상과 감지가 어려운 편입니다.

첨부 · 재귀 (Recursive)

재귀함수는 자기자신을 호출하는 함수를 말합니다. 스택 오버플로우 가능성을 필연적으로 갖는 함수이다보니 선호되는 호출 방식은 아닙니다. 유명한 몇 가지 재귀호출 함수를 소개합니다.

팩토리얼 수열
static int factorial(int n) {
  if (n == 1)
      return 1;
  else
      return n * factorial(n - 1);
}
최대공약수
static int gcd(int p, int q) {
  if (q == 0)
      return p;
  else
      return gcd(q, p % q);
}
피보나치 수열
static int fibonacci(int n) {
  if (n < 2)
      return n;
  else
      return fibonacci(n - 1) + fibonacci(n - 2);
}

  • 생명주기: 지역변수는 선언된 블록(})이 닫히면 소멸하지만, 전역변수와 static 변수는 프로그램 종료까지 유지
  • 인자 전달: 값만 베껴 원본이 안전한 Call by Value vs 주소(*)·참조(&)로 원본을 고치는 전달 방식

세 번째 슬라이드에서는 변수가 살아남는 수명과 함수로 값을 넘기는 방식을 비교합니다. 왼쪽 위의 데이터 영역에 놓이는 전역변수는 모든 함수에서 쓸 수 있지만 프로그램이 끝날 때까지 메모리를 차지합니다. 함수 안에 static 예약어를 붙여 선언한 정적 지역변수는 해당 함수 안에서만 보이지만, 함수가 끝나도 값이 사라지지 않고 다음 호출까지 그대로 유지됩니다.

반면 왼쪽 아래 스택 영역에 만들어지는 일반 지역변수는 선언될 때 태어나 자신이 속한 중괄호(})가 닫히는 순간 소멸합니다. 같은 이름의 변수 i가 겹쳐 선언된 경우에는 현재 위치에서 가장 가까운 안쪽 블록의 변수를 우선 참조합니다.

오른쪽은 함수에 변수를 전달하는 방식의 차이입니다. 기본 방식인 값에 의한 호출(Call by Value)은 원본의 숫자 값만 복사해 별도의 메모리 칸에 넘겨주므로, 함수 안에서 값을 아무리 바꾸어도 호출한 쪽의 원본 변수는 전혀 변하지 않습니다.

반대로 함수 안에서 호출자의 원본 변수까지 직접 수정하고 싶다면, C 언어에서는 원본의 메모리 주소(&)를 포인터(*)로 넘기고 C++에서는 참조자(&) 문법을 사용해 원본 메모리에 직접 접근합니다.

첨부 · 변수의 범위와 생명주기 (Life Cycle)

변수를 호출하면 컴파일러는 정해진 규칙에 의해서 정해진 위치에 순서대로 할당하게 됩니다. 컴파일러는, 현실세계와 마찬가지로, 같은 이름이더라도 어디에 속해있는지에 따라 호출되는 변수를 참조하게 됩니다.
이러한 이유로 코더(Coder)는 호출되는 위치가 함수 안인지 밖인지를 주의해야하며, 만약 외부의 변수를 사용하고 싶다면 추가 문법을 명시해야 합니다.

기본적으로 변수의 Life cycle은 선언될 때 생성되고, 선언된 '}'(중괄호 닫힘)를 만나면 소멸합니다.(실제로 삭제되는 것은 아닙니다.) 정확한 내용은 pointer에서 다룹니다. 일반적으로: 

int i = 9; // 첫째 (전역변수)

int main()
{
  int i = 8; // 둘째
  {
    int i = 7; // 셋째
    {
      int i = 6; // 넷째
    }
    // 위치 1
  }
  // 위치 2
}

똑같은 i라는 변수가 여러번 선언 되었다고 할 때, 컴파일러가 참조하는 변수는 각각 해제되지 않은 최근의 변수를 사용하게 됩니다. 예를들어:

  • 첫째 위치에서는 첫째를 참조합니다.
  • 둘째 위치에서는 둘째를 참조합니다.
  • 셋째 위치에서는 셋째를 참조합니다.
  • 넷째 위치에서는 넷째를 참조합니다.
  • 위치 1에서는 셋째를 참조합니다.(넷째 소멸)
  • 위치 2에서는 둘째를 참조합니다.(셋째 소멸)

첫 째의 위치는 변수가 해제될 수 없는 위치에 선언되었습니다. 따라서 모든 함수에서 사용될 수 있기 때문에 "전역변수"라고 합니다.
전역변수는 높은 범용성을 지니지만, 항상 메모리에 상주하고 있으므로 일정부분의 손해를 감수해야 합니다. 전역변수와 대비되는 개념이 "지역변수"입니다. 지역변수는 함수 내에서 선언되는 변수를 말합니다. 지역변수는 종료와 함께 소멸한다는 것을 주의해야 합니다.

첨부 · 정적 지역변수 (static)

static 예약어는 해당 변수가 호출된 후 유지되도록 요청합니다. 

void foo()
{
  static int i = 0;
  i++;
  printf("foo 호출: %d\n", i);
}
첨부 · 호출(Call) 방법 — Call by Value · Pointer · Reference

변수를 전달하는 방법에 따라 Call by Value, Call by Reference, Call by Address가 있습니다. (포인터 편 참조)

Call by Value
void callbyValue(int);

callbyValue(input);

값(value)를 직접 복사하여 전달합니다. 따라서, 값을 변경한다고 해도 원래 값에 변경이 적용되지 않습니다.

Call by Address (Pointer)
void callbyPtr(int*);

callbyPtr(&input);

주소(address, pointer)를 복사하여 전달합니다. 해당 주소의 값을 변경하기 때문에, 원래 값에 변경이 적용됩니다.

Call by Reference (C++)
void callByRef(int&);

callByRef(input);

변수에 대한 참조(reference 별명)를 전달합니다. 원본 변수를 직접 가리키기 때문에 값의 변경이 그대로 적용됩니다.

첨부 · 가변 인자 (va_list)

참조: https://learn.microsoft.com/ko-kr/cpp/cpp/functions-with-variable-argument-lists-cpp?view=msvc-160

전달해야 하는 인자의 갯수가 변경되는 경우가 발생할 수 있습니다. 예를들어 printf 함수가 그렇습니다.

printf("%d", i); // 전달 인자 2개
printf("%d %d", i, j); // 전달 인자 3개

이를 해결하는 방법은 va_ 구조를 사용하는 방법입니다. 간단한 예시는 다음과 같습니다. 

int addAll(int size, ...)
{
    int _Result = 0;

    va_list vl;
    va_start(vl, size);
    for (int i = 0; i < size; i++)
        _Result += va_arg(vl, int);
    va_end(vl);

    return _Result;
}
