1React · 시작하기 · 명령형과 선언형
직접 고치기에서 결과를 적기로
  • 명령형: 요소를 찾아 만들고 붙이는 순서를 사람이 하나씩 지시 (Javascript의 객체 접근)
  • 선언형: 데이터(state)에 따라 화면이 어떤 모습이어야 하는지만 적고, 고치는 일은 React에 위임

첫 번째 슬라이드는 React가 무엇을 대신해 주는지를 보여 줍니다. Javascript 객체 접근 문서에서는 getElementById로 요소를 찾고, createElement로 새 요소를 만들고, appendChild로 붙였습니다. 이렇게 화면을 고치는 순서를 하나씩 지시하는 방식을 명령형이라고 부릅니다.

명령형은 작은 화면에서는 충분합니다. 하지만 목록에 항목이 하나 늘어날 때 개수 표시도 고치고, 빈 목록 안내문도 숨기고, 단추의 활성 상태도 바꿔야 한다면, 데이터가 바뀔 때마다 고칠 곳을 사람이 전부 기억해야 합니다. 화면이 커질수록 빠뜨리는 곳이 생깁니다.

React는 방향을 바꿉니다. 화면의 재료가 되는 데이터를 state라는 이름으로 한곳에 두고, 그 데이터가 주어졌을 때 화면이 어떤 모습이어야 하는지만 적습니다. 이것을 선언형이라고 합니다.

화면을 적는 단위가 컴포넌트이고, 컴포넌트는 데이터를 받아 화면을 돌려주는 Javascript 함수입니다. 데이터가 바뀌면 React가 함수를 다시 불러 새 결과를 얻고, 앞의 결과와 비교해 달라진 곳만 실제 DOM에 반영합니다. 우리는 데이터만 바꾸면 됩니다.

첨부 · React란

React는 Meta(당시 Facebook)가 2013년에 공개한 화면(UI) 라이브러리입니다. 화면을 그리는 일만 맡고, 주소에 따른 화면 전환(라우팅)이나 서버 통신은 다른 라이브러리와 조합합니다. 그래서 스스로를 프레임워크가 아니라 라이브러리라고 소개합니다.

  • react: 컴포넌트와 Hook을 정의하는 핵심 패키지
  • react-dom: 계산한 결과를 브라우저의 DOM에 반영하는 패키지 (모바일 앱은 React Native가 이 자리를 맡습니다)

이 문서는 React 19와 함수 컴포넌트를 기준으로 합니다. 예전 자료에 나오는 클래스 컴포넌트(class App extends React.Component)는 지금도 동작하지만 새로 쓰지는 않습니다.

첨부 · 같은 화면을 두 방식으로
명령형: Javascript만으로
<ul id="list"></ul>
<script>
  const items = ['우유', '빵', '달걀'];
  const ul = document.getElementById('list');
  for (const item of items) {
    const li = document.createElement('li');
    li.textContent = item;
    ul.appendChild(li);
  }
</script>
선언형: React 컴포넌트
function List() {
  const items = ['우유', '빵', '달걀'];
  return (
    <ul>
      {items.map(item => <li key={item}>{item}</li>)}
    </ul>
  );
}

두 번째 코드에는 "찾는다, 만든다, 붙인다"가 없습니다. 목록이 어떤 모습인지만 적혀 있습니다.

프로젝트 만들기와 폴더 구조

터미널 (PowerShell · bash)
# 1. 프로젝트 만들기npm create vite@latest my-app -- --template react # 2. 폴더로 들어가 패키지 설치cd my-appnpm install # 3. 개발 서버 실행npm run dev ➜ Local: http://localhost:5173/

두 번째 슬라이드는 React 프로젝트를 만드는 과정입니다. React 코드는 브라우저가 그대로 읽지 못하는 문법을 쓰기 때문에 변환해 주는 도구가 필요하고, 지금은 그 도구로 Vite를 씁니다. 터미널에서 첫 번째 명령을 실행하면 my-app 폴더에 React 템플릿이 만들어집니다.

폴더로 들어가 npm install을 실행하면 package.json에 적힌 패키지를 내려받아 node_modules 폴더에 설치합니다. 이 폴더는 용량이 크고 언제든 다시 만들 수 있으므로 Git에 올리지 않습니다.

npm run dev를 실행하면 개발 서버가 뜨고 주소가 출력됩니다. 브라우저에서 그 주소를 열어 두면, 파일을 저장할 때마다 화면이 바로 바뀝니다.

폴더에서 기억할 것은 세 파일이 이어지는 순서입니다. 브라우저는 index.html을 받고, 그 문서가 src/main.jsx를 부르고, main.jsx가 App.jsx의 컴포넌트를 화면에 그립니다. 우리가 고치기 시작하는 곳은 App.jsx입니다.

나머지는 자원과 설정입니다. public에는 그대로 복사될 파일을, src/assets에는 코드에서 import해 쓰는 이미지를 둡니다. package.json은 의존 패키지와 명령을, vite.config.js는 빌드 설정을 담습니다. 설정의 세부는 Vite 시작하기에서 다룹니다.

첨부 · 환경 준비 — Node.js와 에디터

React 개발에는 Node.js가 필요합니다. 브라우저 밖에서 Javascript를 실행하는 프로그램이고, 패키지 관리자 npm이 함께 설치됩니다. 설치 방법은 Javascript 기초문법의 「환경2 : Node.js」와 같습니다. LTS 버전을 받으면 됩니다.

설치 확인
node --version
npm --version

에디터는 VS Code를 권합니다. JSX 문법 강조와 자동 완성이 기본으로 들어 있습니다.

Windows PowerShell에서 npm이 실행되지 않을 때: "이 시스템에서 스크립트를 실행할 수 없으므로…"라는 오류가 나오면 실행 정책이 npm.ps1을 막은 것입니다. npm.cmd install처럼 .cmd를 붙여 실행하거나 명령 프롬프트(cmd)를 쓰면 됩니다.

첨부 · Create React App은 쓰지 않습니다

예전 자료는 npx create-react-app my-app으로 시작합니다. Create React App(CRA)은 2025년 2월에 공식적으로 지원이 끝났습니다. React 팀은 새 프로젝트에 다음 둘 중 하나를 권합니다.

  • 빌드 도구: Vite처럼 변환과 번들만 맡는 도구. 화면 구성은 직접 정합니다. 이 문서의 방식입니다.
  • 프레임워크: Next.js, React Router처럼 라우팅과 서버 렌더링까지 포함한 묶음. 규모가 큰 서비스에 맞습니다.

React를 배우는 단계에서는 Vite가 알맞습니다. 숨겨진 규칙이 적어 무슨 일이 일어나는지 따라가기 쉽습니다.

첨부 · 설치 없이 맛보기 (CDN)

HTML 파일 하나에 <script>로 React를 불러올 수도 있습니다. JSX를 쓰지 못해 createElement를 직접 불러야 하므로 실제 개발에는 맞지 않지만, React가 결국 Javascript 라이브러리일 뿐이라는 점은 확인할 수 있습니다.

<div id="root"></div>
<script type="module">
  import { createElement } from 'https://esm.sh/react@19';
  import { createRoot } from 'https://esm.sh/react-dom@19/client';

  const hello = createElement('h1', null, '안녕, React');
  createRoot(document.getElementById('root')).render(hello);
</script>

첫 화면이 그려지는 경로

3React · 시작하기 · main.jsx
첫 화면이 그려지는 경로
  • 빈 상자: index.html에는 <div id="root"> 하나뿐이고, 내용은 Javascript가 채움
  • 시작점: createRoot(상자).render(<App />) 한 줄이 React와 DOM을 연결
src/main.jsx
import { StrictMode } from 'react'import { createRoot } from 'react-dom/client'import App from './App.jsx' const root = document.getElementById('root') createRoot(root).render( <StrictMode> <App /> </StrictMode>,)

세 번째 슬라이드는 첫 화면이 그려지기까지의 경로입니다. HTML 기초문법에서는 보여 줄 내용을 body 안에 직접 적었습니다. React 프로젝트의 index.html에는 내용이 없고, id가 root인 빈 상자 하나와 main.jsx를 부르는 script 태그만 있습니다.

main.jsx의 처음 세 줄은 재료를 가져옵니다. react 패키지에서 StrictMode를, react-dom/client에서 createRoot를, 그리고 우리가 만든 App 컴포넌트를 가져옵니다.

이어서 getElementById로 빈 상자를 찾고, createRoot에 넘겨 React가 관리할 자리로 지정합니다. render에 넘긴 <App />가 그 자리에 그려집니다. 프로젝트 전체에서 DOM을 직접 찾는 코드는 이 한 줄뿐이고, 그 뒤로는 React가 맡습니다.

render에 넘긴 App은 StrictMode라는 포장으로 한 번 감싸여 있습니다. 이 포장은 화면에 아무것도 보여 주지 않고, 안에 든 컴포넌트를 검사하는 일만 합니다. 무엇을 검사하는지 알려면 먼저 React가 컴포넌트에게 바라는 약속을 알아야 합니다.

React는 컴포넌트가 화면을 그릴 때 한 가지 약속을 지켜 주기를 바랍니다. 화면을 그리는 동안에는 바깥의 값을 읽어 오거나 바꾸지 말고, 받은 값만 보고 화면을 만들어 달라는 약속입니다. 이런 함수를 순수 함수라고 부릅니다.

이 약속을 지키면 두 가지를 얻습니다. 첫째는 안정성입니다. 같은 값을 받은 컴포넌트는 몇 번을 다시 그려도 늘 같은 화면을 보여 줍니다. 둘째는 효율성입니다. 결과가 늘 같다는 걸 믿을 수 있으니, React는 필요할 때 언제든 다시 그릴 수 있고, 그리다가 멈출 수도 있고, 받은 값이 그대로라면 다시 그리지 않고 건너뛸 수도 있습니다.

StrictMode는 이 약속이 잘 지켜지는지 검사해 줍니다. 개발하는 동안 자기가 감싼 컴포넌트들을 일부러 두 번씩 그려 봅니다. 약속을 지킨 컴포넌트라면 두 번 그려도 화면이 똑같습니다. 하지만 그리는 도중에 바깥 값을 건드리는 컴포넌트라면 두 번째 결과가 달라지기 때문에 실수가 금방 드러납니다.

이렇게 그려진 App의 내용은 오른쪽 그림처럼 root 상자 안에 들어갑니다. 이 영역은 React가 관리하므로 우리가 직접 고치지 않습니다.

몇 가지를 덧붙이겠습니다. 순수해야 하는 건 화면을 그리는 부분뿐입니다. 서버에 요청을 보내거나 타이머를 거는 일은 화면을 다 그린 뒤에 실행되는 useEffect나, 사용자가 버튼을 눌렀을 때 실행되는 이벤트 처리 함수에서 하면 됩니다. 그리고 이 약속은 StrictMode를 쓸 때만 지키는 규칙이 아닙니다. React로 만드는 모든 컴포넌트가 지켜야 하는 규칙이고, StrictMode는 그걸 확인해 줄 뿐입니다.

앞에서 그리다가 멈출 수 있다고 했는데, 여러 화면을 동시에 나란히 그린다는 뜻은 아닙니다. 그리던 일을 잠시 멈추고, 사용자의 입력처럼 더 급한 일을 먼저 처리할 수 있다는 뜻입니다.

StrictMode는 두 번 그려 보는 것 말고도 몇 가지를 더 합니다. useEffect를 한 번 더 실행해 보면서 뒷정리를 제대로 하는지 확인하고, 이제는 쓰지 않는 오래된 기능을 쓰면 경고를 띄워 줍니다. 이 검사는 개발하는 동안에만 동작합니다. 실제로 배포한 앱에서는 아무 일도 하지 않으니 속도가 느려질 걱정은 하지 않아도 됩니다.

마지막으로, StrictMode가 모든 실수를 잡아 주지는 못합니다. 두 번 그려도 겉으로 티가 나지 않는 실수는 그대로 지나갈 수 있다는 점을 기억해 두세요.

2026-11-18 · 다음 문서 「JSX와 컴포넌트」에서 App.jsx 안을 채웁니다

첨부 · index.html 원문 
<!doctype html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>my-app</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>

type="module"은 이 스크립트가 import 문을 쓰는 ES 모듈이라는 표시입니다. 브라우저는 .jsx를 읽지 못하지만, 개발 서버(Vite)가 요청을 받아 Javascript로 바꿔서 돌려줍니다.

첨부 · StrictMode가 하는 일
  • 개발 모드에서 컴포넌트 함수와 effect를 일부러 두 번 실행합니다. 두 번 불러도 결과가 같은지 확인해, 숨은 부수 효과를 드러냅니다.
  • 더 이상 쓰지 않는 API를 쓰면 경고합니다.
  • 빌드한 결과(배포판)에서는 아무 일도 하지 않습니다.

console.log가 두 번 찍히는 것은 고장이 아니라 이 검사 때문입니다. 끄지 말고 그대로 둡니다.

첨부 · React Developer Tools

브라우저 확장 프로그램 React Developer Tools를 설치하면 개발자 도구(F12)에 Components 탭이 생깁니다. 요소 탭이 HTML 태그를 보여 주듯, 이 탭은 컴포넌트 트리와 각 컴포넌트의 props · state를 보여 줍니다. 값이 기대와 다를 때 가장 먼저 여는 곳입니다.
