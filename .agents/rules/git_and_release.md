# Project Versioning & Release Directives

## 1. Project Changelog & Version Sync
- Update version numbers in project changelog files (`CHANGELOG.md`, `CHANGELOG-KR.md`, `changelog.json`) and execute release commits **ONLY after the user inspects the work and explicitly assigns the version number (e.g., v1.0.1)**.
- When merging a sub-project branch into `main`:
  - Prepare a draft of the changelog notes first and present it to the user.
  - Obtain explicit review/approval before updating `CHANGELOG.md`, `CHANGELOG-KR.md`, or `changelog.json`.

## 2. Release Versioning & Cache Busting
- Before executing a release commit or push to `main`:
  - Update `window.SiteVersion` and the top version comment in `/modules/script.js` using the format `YYYYMMDDvN` (e.g., `20260814v1`).
  - If updated on the same day, increment `N` (e.g., `v1` -> `v2`).

## 3. Search Index Sync
- The sidebar search uses a prebuilt static index (`/search-index.json`) generated by `scripts/build-search-index.js`.
- Whenever article HTML content or `hierarchy.json` changes, regenerate it with `npm.cmd run build:search` and commit the result together.
- Before executing a release commit or push to `main`, run `npm.cmd run check:search` and confirm it exits with code 0.
